# meristem：人的工作树

> **人递归，模型在一条线里干活。**
> 系统只面对一个人：他有一堆工作，每件工作有多个角度；每个角度是一条线，线上是一段对话，
> 模型带着这个角度的能力（提示词 + 工具）去做，人随时进去接着说。
>
> **性质：目标设计。** 当前代码还停在旧结构（`dispatch` / `leaf` 分工 + 父节点判定 + 子向父交接），
> 这份文档写我们要去的地方。旧设计的全文在 git 历史里（`159a063^:docs/DESIGN.md`），
> 其中仍然成立的部分在 §6 显式收回。

---

## 0. 一句话

> **分叉是人做的，注意力在分叉时分开，收敛也是人做的。**
> 树记的不是"谁命令谁"，是"每条线从哪段上下文长出来的"。

---

## 1. 为什么不是"一道命令下去自动跑完"

这个假设要单独驳一次，因为旧设计正是从它出发的（"递归消除不确定性，直到剩下不可再分的执行步骤"）。

**它本身不是不可能，但不可能靠一个 harness 实现。** 把"拆解 → 分配 → 完成 → 收敛"整条链
交给模型，需要的是模型本身更强（个人化的自改进），不是外壳写得更大。旧设计的实测数据就是判决书：

| 观察到的事 | 数字 |
|---|---|
| 平铺 agent 的 prompt 线性涨（同一件事越做越贵） | 2,529 → 169,760 tokens |
| 指望模型自己把大任务拆完并跑完 | 一晚 2443 节点 / 8648 调用 / 35.7M tokens / 11.5h，**86% 节点从未完工** |
| 自报字段会被 game（模型对自己行为的描述不可信） | 自报 `kind` 被 game 到 69% |
| 没有人在中间校准，判据会漂移 | 根以下只有 3% 的判据提到最初目标里的"钱"；锚点在深度 1 就被换成一组行情字段 |
| 静默截断让模型瞎着干活 | 一个叶子把同一份文件读了 25 次 —— 它看到的是断在半句的截断，而且没人告诉它那是截断 |

（更全的表在 `159a063^:docs/DESIGN.md` §6。）

**结论**：漂移发生在中间每一次分配里，而人的介入只有两头（入口谈成、事后看结论）—— 粒度太粗。
所以递归的主体从模型换成人：**人负责拆和收，模型负责在一条线里把事做完。**

### 1.1 那 harness 还能增强什么

只有一句：**在相同的上下文下，以不同的能力、从不同的角度分叉。**

人脑子里同时有几个念头时（把刚才的讨论写成文章 / 继续把技术细节聊透 / 先把某件事做掉），
系统不该替他决定，而该让他一句话就把这些念头摊成几条各自独立的线，并且每条线
**看到同一段上下文（血缘往上拼，或一份总结）**、**带着不同的注意力（提示词 + 工具）**、
**各有自己的做事目录（缺省与父同目录）**。

## 2. 结构：树 = 上下文血缘

- **节点 = 一条线**：一段平铺对话 + 一个明确的活儿。人能进去直接说话。
- **边 = "从哪段上下文分出来的"**，不是"谁向谁汇报"。
- 于是这些概念一起消失：分配 / 叶子的分工、父给子的形式格子、子向父的结论交接、
  父对子的判定、兄弟之间的通信。
- **节点之间不通信。** 它们之间只有三条媒介：**血缘**（分叉时沿父往上拼出的那段上下文）、
  **工作区**（文件）、**人**。人是唯一的总线，也是唯一的判定者与收敛者。
- 树的价值只剩两条：**归属**（这条线是从哪个念头长出来的）与**上下文**（往上拼到该停的线为止）。

## 3. 节点是什么（新的格子）

| 面 | 谁给 | 说明 |
|---|---|---|
| 名字 / 目的 | **人**（人写，或由代码取人第一句的前几个字） | 一屏能看见每条线在干什么，靠的就是这一行。**不许模型生成摘要冒充它** |
| 角色 | **人**（从预置能力包里选） | 决定这次带上哪些注意力、哪些手（§4） |
| 上下文来源 | 分叉时定死 | **默认**：沿血缘往上拼祖先的对话，碰上"自带底"的线就停；**总结分叉**：先由总结角色（乙）从历史里抽一份相关的底（**只总结、不回应用户**），再换上新角色（丙）开局并由它回答用户那句话 —— 这条线从此自带底 |
| 做事目录 | 出生时定死 | 人在分叉时可以给一个；缺省与父同目录（一棵树通常就是一个工作目录） |
| 对话 | 模型与人 | 平铺，不分层；一条回复可以标“是在哪个角色下产生的”（只有总结分叉才需要） |

在 atree 眼里这一整张表只有两样东西：**结构**（父 / 边界 / 出生顺序）与**不透明的 `props`**
（名字 / 角色 / 做事目录）—— 通用树包一个字段都不解释。

**没有"交付形状"要填。** 一件事的结果就是工作区里的产物 + 它对人的话。

---

## 4. 角色 = "注意力 + 手"的开关，不是类型

角色只决定两件事：**它自己的系统提示词**（一份 xml 模板，填上自己的手与技能）与**给哪些手**。

- **角色是数据，不是代码分支**：加一个"做特定类视频"的角色 = 加一份数据；不许出现
  `if role == ...` 这种枚举警察。
- **"纯节点"就是证据**：全关（零提示词、零工具）也合法 —— 那是一条纯对话线。
  计划 / 编程 / 调研 / 写作 / 做视频…… 都只是预置配置。
- **角色由人选，不许模型自报**（依据是 §1 表里那条 69%）。模型可以**建议**"这活要不要换个角色"，
  那是人话，不是结构动作。
- **"计划节点"不是 orchestrator**：它开不了节点、派不了活。它的产物是**给人看的分解建议**，
  人看完说一句"就按这个分"才变成结构。
- "怎么跟人说话 + 纪律"这两段每个角色的 xml 里都得有：换角色不该换说话方式。

## 5. 不变量（改代码前看）

1. **树就是账。** 不另建成果库 / 记忆 / 索引 / 汇报层，也不自动生成"向上摘要"。
   记录就是事实本身 —— 任何"另存一份"都会跟真实发生的那份漂移。
2. **能机械验的，绝不许模型自报。** 谁在跑由作业表说、谁该说话由账说，角色由人选，引用是引用
   （指得出节点 / 消息 / 文件，不是模型复述）。
3. **结构动作只有人有。** 分叉由人主动，模型只能提议。这条不写死，"人主动分叉"会在实现里悄悄烂掉。
4. **判断自由，形式化只用于交付。** 过程里不填表（没有"进度""结论"这类格子）；
   要形式化的是**给出去的产物**和**人对节点的可读面**，不是格子里的字。
5. **零计数器。** 没有轮次 / 深度 / 节点 / token / 时间 / 并发上限 —— 分叉由人做，同时在飞的东西本来就不多。
   **该动的线全部一起推**（并发不是一个要调的量）：节点都是人手动开的，完全可控。
   （这条管的是**配额** —— “你做得太多了”。一手的**超时**不属于配额：卡住不是“需要更多时间”，
   是“没有回应”，它归那只手自己（§9.9）。）
   想让它更收敛就把事实说清楚，不是加一个上限 —— 上限会把"真的需要"和"在打转"混为一谈。
6. **给养按注意力选，选了什么必须看得见。** 进模型的事实要从有限、可枚举的集合里取；
   截断 / 翻页 / 超时都要说清"还有多少、怎么取回"（一个说得出来的限制不是惩罚，说不出来的才是）。
7. **人是唯一对端。** 系统里没有"需要被满足的上层"，只有一个人：他不满意就继续说。
   **人不在场 = 树在休息**，这是常态，不是结束。
8. **不重写历史。** 过期的东西归档，不删改：旧结论保留，新的运行得出新结论。

## 7. 边界与未定

**已知代价（接受）**

- **人的带宽是瓶颈**：分解与收敛都在人身上。所以 harness 的优化目标不是"完成率"，
  而是"**分解与收敛的边际成本**" —— 一个动词能分叉且自动带上该带的上下文，一屏能看见每条线的人写目的、角色与手上有没有没回来的活。
- **没有自动汇报**：线多了以后，人只能靠"人写的名字 + 手上还有没有活"扫一眼。
  所以这两样必须是**事实**，而且必须极便宜。
- **一个人 = 一棵树 = 一份账**：终身增长。账的分片 / 归档 / 惰性加载是这套定位必须面对的工程事实
  —— 旧设计里"一场会话一棵树"顺带解决了它，现在没有那层分片了。
- **全局一棵树**：树一直在那儿，会话不是分片 —— **新会话 = 根的一个子节点**（一次以根为父的分叉）。
  所以没有"新建 / 接着哪个会话"这类命令，只有**分叉**与**切节点**（切节点只是"我站在哪"，不写账）。

**还没定**

- **模型能不能提议分叉**：倾向"能说一句，人点头才开"；但"模型得先知道有节点和角色这回事"，
  这句话怎么写还没定。
- **重复 / 定时任务**：触发条件（人给的间隔 / cron / 事件）挂在节点上，到点开一条新线 —— 形态没定。
- **同节点的多条线**（"同一件事再开一条"）算新节点，还是同节点的另一段对话 —— 没定。
- **多用户**：一人一棵树 —— 到那时才需要一份"这底下有哪些树"的清单（现在刻意不做这类接口，
  也不为它留冗余）。
- **静默超时**（多久没有新输出算卡住，而不是总时长）：对“等输入 / 挂死”那一类比总时长准得多，
  但会多一条时间语义 —— 先不做，等有实际证据。
- **没有时间参数那些手的兜底值**（MCP 手）：现在按“底座给一个值并说出来”处理，具体多少待定。
- **归档与休眠的语义**；**角色清单谁来定**（预置包的范围）。

## 8. 包划分（主坐标轴 = 变更理由）

Monorepo（Bun workspaces），五个包。主坐标轴宣布为：**谁的命令会让这段代码动** —— 每个包的变因清单互不重叠，
所以一次真实改动只落在一个包里；混用第二根轴（比如"按功能分"）会立刻出现"放哪儿都自洽"的去处，然后漂移。

| 包 | 变因（谁让它改） | 对外只有这一面 | 内部依赖 |
|---|---|---|---|
| `@meristem/atree` | 数据结构与存取机制 | **一棵通用的树（参考 DOM）**：节点（父 / 不透明的 `props` / 边界 / 出生顺序）+ 每个节点自己的内容数组 + 沿枝拼接（`assemble`）+ append-only 账。对外只有 `load(path)`（有树折出来，没有就是空的内存树，真写入才落盘）/ 两类操作 / `close()`。**不含任何业务语义**：`props` 与内容都是上层给的类型，一个字段都不解释；落盘格式是内部机制 | 无 |
| `@meristem/tui` | 组件自身的实现 | 只吃 props 的组件（消息流 / 思考行 / 手卡片 / 输入框 / 树条带 / 状态条 / 外壳） | 无 |
| `@meristem/roles` | 能力（一块能力因什么而变：它的提示词、它的手、它的技能） | **只有两个面**：LLM 面（`Role`：`system()` / `hands()` / `run`，外加**作业的形状** `Job` 与三只作业共享手）+ 人面（`start` / `list` / `get`） | 无 |
| `@meristem/harness` | 生命周期（开 / 恢复 / 推进 / 等人 / 出生 / 收手：唤醒、上下文组装、错误处置、出生与调度规则） | **操作 + 事件**：`Tree`（`resume` / `say` / `fork` / `stop` / `jobs` / `cancel` / `retry`）+ `subscribe`；另露**上层词汇**（`LineProps` / `WireMessage` / `Usage` / 配对规则）与 `createClient` | atree, roles |
| `@meristem/terminal` | 交互与展示（业务）+ **部署的事实**（`.env` 怎么解释、怎么分给各包） | 一屏界面 + 入口 + 装配 | atree, roles, harness, tui |

**依赖方向**（实测无环）：

    atree, tui, roles  → （无）    # 三个底层：数据 / 组件 / 能力
    harness            → atree, roles
    terminal           → atree, roles, harness, tui

**能力全在角色后面**：harness 不认识工具 / 技能 / 提示词 / MCP 这些词，roles 也只对它露两个面。对它而言，
一份角色只意味着"给我一段 system、一组能伸的手、执行一次拿回一个作业"。所以：

- **角色定义 = 一个 xml**：人写一份 xml 就是一个角色 —— 一段提示词（纯文本，无模板语法、无占位符）、
  "点名要哪几把内置手"、要哪些技能、要连哪些 MCP 服务。装载器把它变成 `Role`；内置角色也是 xml，
  走同一条路径，同名当场报错 —— 所以加一个角色就是加一个文件，绝不是改代码。
- **system 由装载器按固定顺序拼**：`preamble`（人写的提示词）→ `tools`（一行一只：名字 + snippet）→
  `rules`（各只手贡献的纪律条目，去重）→ `skills`（名字 / 描述 / 路径 + 怎么读）。
  每一节是一对同名标签包住的几行（`<tools>` / `<rules>` / `<skills>`；空节整个不出现），
  人写的 `preamble` 原样放最前面、不包标签；不认识的标签 / 手名 / 技能名当场报错，不当成"没写"。
  所以"模型知道自己有哪些手 / 哪些技能"不靠人复述：**技能没有专门的手**（清单给路径，正文用 `read` 读），
  手的完整语义只在 schema 那一份，system 里只放一行索引。
- **配置住装配层，包只收自己需要的值**：数据根 / 这棵树的账文件 / 角色目录 / 技能根 / 模型引用 /
  端点覆盖 / 钥匙的**变量名**由入口解释一次，再分头交过去（树的账文件给 atree、角色目录与技能根给 roles、
  模型引用 / 端点覆盖 / 钥匙给传输 —— `start` 只收端口，一个值都不收）。**包不定义配置，也不自己读 `.env`**
  —— 包自己读环境变量就是第二份定义，换个加载来源（文件 / 命令行 / 测试传参）还得改包。
  密钥只写变量名、取完立刻交给传输层：不进配置对象、不打印值，报错只说来源。
- **模型是引用，不是三个平铺的字符串**：`provider/model` 一次决定端点、模型目录（元数据：上下文多大 /
  支不支持思考与工具）与钥匙从哪来；解析在传输层（吃到 pi-ai 的模型目录），别的包不许再解释一遍引用。
- **通用树 + 上层词汇**：atree 只认结构（父 / `props` / 边界 / 内容数组）与两类操作（查写节点、查写内容），
  **沿枝拼接的机制也住它那儿**（`assemble`：往上接、碰上边界停）；名字 / 角色 / 做事目录
  （`LineProps`）与消息形状（`WireMessage`）全是 harness 的定义，对 atree 不透明。
  所以"这条线叫什么、干什么"这类改动一行都不动 atree，换一棵别的树用 atree 也不用改它。
- **对内共享，对外只露角色**：roles 内部共享同一把 bash 手、同一个技能加载器、同一套 MCP 连接；
  角色只是在 xml 里点名要哪些。不许每个角色各写一份实现。
- **手没有来源之分**：内置手与 MCP 手到 harness 眼里同型（名字 + 描述 + schema + 执行）。
  MCP 在 xml 里只声明**怎么连**（`url` 一个地址，或 `command` 一行命令行；服务名与工具名由那台服务自己给）；
  **下载 / 安装不在程序里做**（那是人的额外流程）；连不上 / 起不来 → 抛错，那个角色不成立。
  **手的语义不在提示词里重复**：schema description 是唯一一份说明，所以提示词里没有 `{{hands}}`。
- **角色不认识节点**：`Role.system()` 不带任何外部对象 —— 它把自带的 xml 模板填上自己的内容（手、技能）就返回。
  节点级的事实（血缘、做事目录……）走 msgs，不进 system。roles 的数据也是它自己的（一份列表），不请 atree 代存。

**三条守门**（由测试执行，不靠自觉）：

1. **跨包 import 只允许出现在上面那张表里**，而且必须在 `package.json` 里声明（没声明的 import 直接失败）。
2. **不许用相对路径跨包**（包名 import 才能被工具守住）。
3. **词表只有一处**：树的结构字段（atree）、`props` 与消息形状（harness）、事件类型，各只有一份定义。

接口只暴露"不因内部变因而变"的那部分：账怎么分片、手怎么瘦身输出、提示词怎么写，
包外面都看不见。

## 9. 作业：一次执行的生命周期

**一句话：手伸出去就一定是作业。** 这次执行立刻结束（读一个文件、`echo`）= 一个**已经结束**的作业；
这次执行还没回来（`cargo test`、远端 MCP 调用）= 一个**还在跑**的作业。模型侧看不见这个区别 ——
工具的 schema、描述、它要写的参数，一个字都不改。

**判据是"这次执行"，不是"这只手"。** 同一个 `bash` 手，跑 `echo hi` 是立刻结束，跑 `cargo test`
是还在跑 —— 这取决于模型写了什么命令，**动手之前谁都算不出来**（也正因为算不出来，才不能把它
写进任何一只手的声明里）。所以这个判断只存在于一个地方：**运行时那个 `Job` 有没有结束**。

**Job 的四个面向**（同一个对象，四方各看自己那一面）：

| 面向 | 它看到什么 | 谁提供 | 谁消费 | 铁律 |
|---|---|---|---|---|
| **手（roles）** | 一次执行的生命周期句柄：起、输出、取消、超时、最终交代 | 作业底座（roles 的共享件，**一份实现**） | 每只手的实现 | 手只管“起这次执行”与“我最后想说什么”；不碰线、不碰模型、不碰界面 |
| **模型** | `tool_calls` + 两条带作业 id 的消息（起手 / 结束）+ 三只共享手 —— 它**不需要**“异步”这个概念 | roles（共享手、消息由 harness 写） | 模型 | 只读事实、不阻塞（没有 wait 手）；**配对由它自己认**（靠内容里的作业 id） |
| **树（harness）** | 起手、起手一条回话 / 结束一条消息、settle 后叫一声；各条线互不等待（一条慢不堵别人）；同一个节点同时只发一次 | harness | harness 自己 | 只碰**结构**（位置 / 顺序）：一个字的文本都不写、不判断长短、不设统一超时、不轮询、不替模型编交代 |
| **人** | 树条带上的记号、手卡片（名字 / 参数 / 已跑多久 / 输出）、红字与重试 | terminal 显示 + harness 的 `jobs()`（输出自己跟着 `Job.stream()` 走） | 人 | 显示的是**作业自己说的**事实，不是猜的；没有"进度事件"，树也不为它装时钟 |

四个面向分别落在 §9.3（手怎么包）、§9.4（模型怎么知道）、§9.2 末（树自动做什么）、§9.2 末（人看什么、能做什么）。

### 9.1 为什么不是“给某只手加开关”

旧框架（omp / llm-sh）把长命令当成 **bash 这一只手的特例**：于是有 promotion、`async: true`、
`wait_ms` 阈值、“别轮询”文案。特例的路子有三个代价：

- 每只手都得自己判断“我算不算长的” → 一块能力一个策略，必然漂移；
- 模型也得学“哪只手是异步的” → 同一件事有两套说法（违反 §5.2 的单一来源）；
- 而这件事跟“是哪只手”无关：**执行与对话的时间尺度本来就不同** —— bash 会跑几分钟，
  MCP 打远端、网络抖动、将来任何一手都会。

所以**不按手分，按层分：包裹只发生一次，在 harness 上**。

### 9.2 层面归属

| 层面 | 干什么 | 不干什么 |
|---|---|---|
| **atree** | 什么都不包 | **作业不进账**：它活在进程里（重启即不存在），“还没回来”从账推得出来（`assistant` 那条 `tool_calls` 后面没有回话）。账里只进事实：起手那条回话、结束那条消息 |
| **roles（`jobs/`）** | `Job` 的形状；**作业表**（模块级内存结构：登记 / 摘除 / 按 `space` 筛）；底座两个原语；三只共享手 | 不认识节点 / 消息 / 角色 —— 只认 `space` 与作业事实 |
| **harness** | **起手、写账、唤醒**：起手一条回话、结束一条消息、settle 时唤醒这条线；调度跳过“还有活”的线 | 不写一个字的文本、不判断长短、不设统一超时、不轮询、不配对 |
| **terminal / tui** | 显示（树条带记号、手卡片、红字）与人的动作（取消 / 重试 / 插话） | 不解释作业语义 |

`Job` 的类型为什么住 roles 而不是 harness：依赖方向是 harness → roles，roles 不许 import harness（§8）。
先例：`RoleId` / `SUMMARY_FORK` 就是这么放的 —— 谁定义、谁消费，分得开。

**作业表是“谁在跑”的唯一一份**（住 `jobs/table.ts`，模块级，Job 机制自己维护）：登记与摘除都由底座做
（`Hand.run` 内部），手不用自己往表里放东西，树也不写它 —— 树只**读**它算“这条线还有没有活”、
界面拿去看、`job_list` 按 `space` 筛。表里只放**还在跑**的作业：一结束就摘掉，所以它天然有界
（交代已经进账，输出不再有人要）。树不需要另做一张句柄表：它自己 await 着那些 `Job`。

**树自己做的（不需要任何旋钮）**：

1. 起手：`hand.run(args, ctx)`，`ctx` 只有两样 —— `outputRoot` 与 `space`（= 这个节点）；
2. **起手一条回话**：往账里写一条 `role: "tool"` 的回话，内容 = `job.report()`
   （还在跑 → “作业 #abc 已起…”；已经结束 → 结果）；
3. **结束一条消息**：若还在跑就 `await job.wait()`（**从不 poll**）—— settle 时写一条 `role: "user"`
   的消息（内容 = `report()`，同一个作业 id 在里面）、**唤醒这条线**；
4. 调度时跳过“还有作业在跑”的线（§9.5 的唤醒条件）；
5. 人取消 → 转发 `job.cancel()`；`stop`（收手）→ 取消所有在跑的作业（取消的交代仍是事实，照样进账）；
6. 模型接口失败 → 跳过这条线 + `Event.transport_error`（不入账、不自动重试，§9.8）。

**树绝不做的**：判断这一手会长不长（§9.3）；生成任何文本（消息内容一律来自 `report()`）；
设统一超时、轮询、重试、配对（§9.6）；因为作业多就限并发（§5.5）。

**面向人 —— 看什么、能做什么**：

- **看**：这条线上有几个作业在跑（树条带记号）、每个作业的名字 / 参数 / 已跑多久 / 现在吐了什么
  （手卡片：交代问 `report()`，**吐出来的东西自己遍历 `Job.stream()`**）、模型接口失败的红字；
- **做**：取消某个作业、重试模型接口失败的那条线、照常插话（作业在跑时插话就是 §9.5 那一行）；
- **不骗人**：显示的是**作业自己说的原文**，不等于最终交代（后者才进账、才给模型）；界面只显示事实。

### 9.3 `Job` 的形状

```ts
export interface Job {
  readonly id: string;      // 稳定名字（底座给）：账里给人看的那行、job_output/job_cancel、界面都用它
  readonly space: string;   // 在哪个**空间**（由树在调用这只手时给；不透明，roles 不解释）
  readonly at: number;      // 起于什么时候（“已跑多久”从它算）
  readonly name: string;    // 哪只手起的

  /** **用这一手自己的话说“我现在怎么样”**：还在跑 → 已多久 / 吐了多少；结束 → 最终交代
   *  （结果 / 失败 / 被人取消）。这是作业的文本**唯一出口** —— harness 一个字都不拼。
   *  每一句都带 `作业 #id（名字）：` 那一行：起手那条回话与结束那条消息靠它配对（§9.6）。 */
  report(): string;

  /** 现在吐了什么（**原文：不裁剪、不折叠**）：给人看进度，也给 `job_output` 用。 */
  output(): string;

  /** 吐了多少字（总数）：`report()` / `job_list` / 界面都读它，不各自去数（量 `output()` 要拼整段）。 */
  produced(): number;

  /** **跟着这块输出走**：先给已有的，再给新来的，作业一结束就收（界面那张卡片自己遍历它，
   *  所以没有"进度事件"这回事，树里也不用装时钟）。 */
  stream(): AsyncIterable<string>;

  /** 取消：结局仍是一条交代（“被人取消了”），不是特殊状态。 */
  cancel(): void;

  /** 等它结束（幂等）；结束后 `report()` 就是交代。 */
  wait(): Promise<void>;
}
```

**手拿到的是事实与数据，不是回调**：`HandContext` 只有两样 —— 这条线的 `outputRoot`、
这次执行所在的 `space`（树在调用时给；roles 只当键用，不解释它的含义）。
**作业表不在上下文里**：它是 `jobs/` 那一块的模块级内存结构（`table.ts`），手要按空间筛就调那一块的
查询函数。手要跟人说话只有两个口子，都在作业上（输出给人看、交代给模型）—— 手没有第三个出口。

**压缩不在这里。** 作业与手都**原样给**：跑出多少就是多少，不截断、不折叠（`output()` 与交代都不动它）。
要折叠是**发送边界**那一层的事 —— 它裁掉多少、怎么取回，由它自己说清（§5.6：说不出来的限制才是惩罚）。

**手怎么包（底座的两个原语，手只用它们，不许各写一份）**：

| 原语 | 包什么 |
|---|---|
| `settled(facts, 执行)` | “已经开始、且立刻/很快结束”的执行 → 一个**已经结束**的作业（`read` / `write` 用它，语义一行都不用改） |
| `background({ space, name, chunks, done, stop, timeout })` | “起进程 / 发请求、之后才回来”的执行：`chunks` 原样收进输出（不许反向背压；**不裁剪**）、`stop` 必须真停（杀整棵进程树 / 断连）、`timeout` **必给**（`0` = 明说无限期）；**还在跑时 `report()` 的进度句由底座按事实说**（作业 #id、名字、已多久、吐了多少） |

手因此只需要写两样东西：**怎么起这次执行**、**结束时想说什么**（错误与取消都在这里面 ——
它们只是交代，不是状态）。进度句不用每只手自己拼（§5.2 的单一来源）。

**没有一处代码需要判断“这次会不会跑很久”。** 手只做一件事：把执行起起来，返回 `Job`（跑 `echo`
的那个 `Job` 在返回之前就已经结束了）。harness 不问长短，它只读一个事实：这个 `Job` 结束了没有。
所以“短命令”与“长命令”走的是**同一条代码路径**，区别只是 settle 的时刻 ——
`llm-sh` 的“等多久算太长”那个阈值，在这里连落脚的地方都没有。

状态只有两个：**在跑 / 结束**。没有四态机 —— “失败”“被取消”都是**交代**（role 写的文本），
不需要 harness 分类（也就不会出现第二份说法）。

### 9.4 模型怎么知道作业

1. **手一伸出去它就知道**：那条 `assistant` 消息里的 `tool_calls` 是它自己写的；紧接着那条回话里
   带着**作业 id** 与“现在怎么样”（§9.5）。
2. **在跑期间**：作业有三只**共享手**（所有角色都有，不必在 xml 里点名）：

| 手 | 语义 |
|---|---|
| `job_list` | 这条线上现在有哪些作业在跑（id / 名字 / 已跑多久 / 吐了多少） |
| `job_output(id)` | 看某个作业现在吐了什么（原文） |
| `job_cancel(id)` | 不想让它跑了 |

   它们拿作业只有一条路：`HandContext.space` + 作业表 —— **按空间筛**：只有**这条线上起的**作业在列；
   从父线继承下来的消息里提到过的那些作业不属于它（那是别的空间里的，早就结束了）。
   这三只手**本身也是作业**（立刻结束的那种）—— 不为作业另立一套协议，结果照常进账。
   它们的 `description` 要写明两件事（schema 是唯一语义来源）：**输出原文 ≠ 最终交代**；
   **别拿 `job_output` 当轮询手段**（要等就说完这一轮，作业结束会叫醒你）。
3. **结束时的交代**：进账（`role: "user"` 那条消息，作业 id 在里面）。

**不给 `job_wait`。** 模型不需要等，因为**等是自动的**：它说“我起了 `cargo test`”就把这一轮
说完了，作业结束时这条线会被叫一声 —— 它每次开口都发生在“该它说”的时候。给它一只 wait 手，
等于把“阻塞”和“轮询”请回模型手里，阈值那一整套也跟着回来（§9.7）。

### 9.5 消息怎么走（起手一条、结束一条）

**唤醒条件**：一条线被推给模型，当且仅当 —— **该它说**（最后一条是别人说的话 / 有手的交代回来了）
**且这条线上没有还在跑的作业**。于是模型面前只有三种情形：手的交代全部回来了、人插话、或者它自己主动伸手问。

| 时刻 | 账里 | 模型看到 |
|---|---|---|
| 伸手 | `assistant` 消息（含 `tool_calls`） | 同左 |
| 起手 | 一条 `role: "tool"` 的回话，内容 = `job.report()`（还在跑 → “作业 #abc 已起…”；已经结束 → 结果） | 同左 |
| 结束（正常 / 失败 / 被取消） | 一条 `role: "user"` 的消息，内容 = `report()`（同一个作业 id） | 同左（作业 id 让它认得出这是哪一手的回音） |
| 模型主动看进度 | `job_output` 的结果（一次普通工具执行） | 那条结果 |

**一条线一次只做一件（按节点隔离）**：投给某条线的事（人的话、作业结束、开树、重试）都排在
这条线**已经排上的事后面** —— 所以吐字期间人说的话不会插到那句回答前面，而是**等它说完再进账**：
账上的顺序就是事情发生的顺序。并发控制只有这一条，靠的是"这件事属于哪个节点"，不是状态机、也不是锁。

**为什么起手就写一条回话**：`tool_calls` 条条有回话是 provider 的硬要求；起手这条正好把它满足掉，
于是**程序不需要任何配对结构**（§9.6），也不需要“作业还在跑时编一条占位” —— 那条回话是事实
（“已起”是已经发生的事）。

**已经结束的手只写一条**：`read` / `write` 这类立刻结束的执行，在树去看它之前就已经结束了
（`report()` 直接是结果）—— 那一次写下的那条 `tool` 回话本身就是结果，**不再写第二条**：
“内容没变就不写第二次”（两条一模一样的消息是噪音，不是事实）。

**“不自动补”这条纪律管的是账**：账上不编。**进程崩在起手与结束之间**时，账上会留下一条
“伸出去、没回话的手”，作业却随进程一起没了 —— 这条线就**停住不推进**（不替它编回话，也不自动修），
人要接着干就分叉一条新线。

### 9.6 配对是模型的事，不是程序的事

程序**不记**“哪条回话配哪次调用”：没有 `toolCallId`，没有 `answers`，没有配对表。
作业 id 拼在消息**内容**里（起手一条、结束一条），模型靠那个 id 自己把前后对上 ——
这本来就是语言模型擅长的事，而我们少维护一份会漂的映射。

**两个 id 的分工**：账里的参照物是**我们的**（`WireMessage.id` = 消息自己的稳定 id，写账时定死）；
provider 要的 `tool_calls[].id` / `tool_call_id` 是**临时物**，由传输层**出网时现造**
（同一段历史每次请求各造一套，互相不认识也无所谓）。一句话：**临时 id 不进账，记账 id 不出网**。
（临时 id 换个 provider、甚至同一段历史再发一次都可能变 —— 拿它当记账字段，追溯与复现都会碎。）

**provider 那边为什么不用管**：每个 `tool_calls` 在**起手那一刻**就有一条回话写在它后面（§9.5），
所以历史天然成对 —— 不需要补位、不需要归位、不需要在组装时做任何改写。

### 9.7 阈值、promotion、注册表为什么都不需要

| llm-sh / omp 的东西 | 在我们这里 |
|---|---|
| `wait_ms` 阈值 / “等多久才后台化” | 不存在：那个阈值是“调用方的 turn 有多长”，而我们**没有 turn** —— 推进是长期在跑的（谁都不等谁） |
| promotion（前台托管 → 后台） | 不存在：一开始就没有“前台托管”这回事 |
| `run_or_background(wait_ms=…)` | 不存在：**每一次执行本来就是作业** |
| 作业注册表 + 消费标记 | **有表**（`jobs/table.ts`，模块级），但里面只放“还在跑”的作业、只读不消费：交代进账就是交付，界面看的也是同一张表，没有第二份投递状态 |
| 保留期 / dead-letter / 重试退避 / 投递状态机 | 不需要：交代进账就是交付；进不了账的（模型接口失败）归人（§9.8） |

### 9.8 模型接口失败：算人的

作业是“手”的事；**模型接口失败不是任何一手的事**（它不是 role 能定义的东西）。所以：

- **不入 msgs** —— 那条线手里的事实没变，凭什么往对话里写一条；
- **循环跳过这条线**：不推进、不自动重试、不编交代；
- 错误给界面（红字，带来源与原因）；
- 界面上有一个**重试**（`Tree.retry(node)`），只干一件事：把这条线重新放回推进。

harness 里因此没有 `error` 态，也没有 `Event.error`：错误要么是一段交代（手的），要么归人（接口的）。

### 9.9 超时：每一只手自己的事（不然会静默卡死）

**缺口**：作业不结束，这条线就永远不被唤醒。而模型做探索性尝试时经常写出跑不完的东西
（性能很差的脚本、等输入的交互式命令、挂死的远端调用）—— 人不在场时这条线就静默死掉。
所以**必须有一个说得出来的超时**。它落在哪一层，判据是变因：

| 层面 | 该不该定超时 | 为什么 |
|---|---|---|
| **手（roles）** | **必须**：每一手都要能回答“多久算太久” | “太久”取决于这手在干什么：`cargo build` 五分钟正常，`read` 五秒都算久。这是**能力语义**，和它的 `description` / `snippet` 同源 |
| **作业底座（roles 共享件）** | 起执行时**必须有一个超时值**：请求给的 / 手自己的缺省 / 对**没有时间参数的手**（MCP 服务给的 schema 里没有）由底座兜底 | 强制的不是某个数值，而是**“没有‘忘了’这个状态”**（§12 的精神：能机器核的别靠自觉）。`0` = 明说无限期 |
| **harness** | **不设**统一上限 | 它不认识工具（§8），只该知道“这手回来了没有”。一个全局值必然要么误杀（长活）要么没用（短活） |
| **界面** | 显示“已跑多久” + 取消键 | 人在场时由人判断；人不在场时靠第一行 |

**超时的结局是一段交代**（不是特殊状态、不是错误态）：`跑了 120s 还没结束，把它杀了；
要跑更久就写 timeout=<更大的值>`。于是这条线**继续**，模型看到事实、自己改做法 ——
这正是 §5.6 那条“限制必须说得出来”的老纪律（旧设计里“bash 超时要说清跑了多久、被杀、怎么跑更久”）。

**超时值从哪来（三层，逐层退）**：

1. **调用方给的**（能收时间参数的手一律在 schema 里收）：模型自己写的命令，它比谁都清楚“这条要多久”
   —— 预期久的命令就该写更大的值（bash 的 `timeout` 就是这一层）。**没有“某一手强制某个值”这回事**：
   强制等于替模型决定，而它才是那个知道自己在跑什么的人。
2. **手自己的缺省**（调用方没写时）：这个数必须写在它给模型看的说明里（“不写就 120s”），
   否则模型没法在这个事实之上做判断（§5.6）。
3. **底座的兜底**（这只手压根没有时间参数，比如 MCP 手）：由底座在包一层给一个值，
   而且**这件事要说出来**（“这只手没有自己的超时，统一按 N 杀”）—— 说不出来的限制才是惩罚。

**预期更久的命令永远有出口**：模型给更大的值，或 `0` = 明说无限期（它自己的选择，且看得见）。

**三层保险**：

1. **手**：必给超时（编译期强制）+ 超时结局说得出来；
2. **底座**：取消与超时都必须**真的停得住**（bash 杀整棵进程树、MCP 断连并放弃请求）——
   “停不住”是实现缺陷，不是设计缺口，所以验收要求“取消后无残留子进程”（§9.10 第 4 条）；
3. **界面**：在跑的作业一等显示 + 已跑多久 + 取消键（人在场时人处置）。

### 9.10 验收（断行为）

1. **同一只手**（`bash`）跑 `echo hi` 与跑 `sleep 2` 走**同一条代码路径**：都产出作业、都在结束时写回一条交代 ——
   区别只有 settle 的时刻（没有一处代码判断“这次会不会很久”）。
2. 起手写一条 `tool` 回话、结束写一条 `user` 消息，两条都带**同一个作业 id**，内容都来自 `report()`
   （已经结束的手只写那一条：内容没变就不写第二条）；
   账里**没有**任何程序编的回话（进程崩在中间时留下的“没回话的手”，那条线停住不推进）。
3. 作业结束后唤醒那条线；结束那条消息 **= settle 那一刻的 `report()`**（内容里自带作业 id 与用时）。
4. 人取消 → 交代是“被人取消了”（不是特殊状态）；取消后进程无残留子进程。
5. 配对不由程序做：账里怎么记就怎么发给模型（`tool_calls` 后面总有起手那条回话），没有归位/补位逻辑。
6. 模型接口失败 → 账里一个字都不多；界面有红字与重试；重试后这条线继续。
7. `job_output` 看到的是**原样输出**：完整、不裁剪，运行中就能读到；但它仍不是最终交代（后者在结束时进账）。
8. 跑不完的一手（性能很差的脚本 / 等输入的命令）在超时到点时结束，交代里说清“跑了多久、被杀、怎么跑更久”，
   这条线**继续**（不静默卡死）。
9. **模型能自己给时间**：预期更久的那条命令写更大的 `timeout`（或 `0`），确实不被按缺省杀掉。
10. 一只**没有时间参数**的手（MCP）也能在底座兜底到点时结束，且交代里说得出那个兜底值。

## 附：一句话回顾

- 人递归，模型在一条线里干活 —— 系统唯一要面对的是人。
- 树是上下文血缘，不是任务委派：边上是"从哪段上下文分出来的"。
- 分叉是人主动的；模型没有结构动作，只能提议。
- 角色是"注意力 + 手"的开关，是数据：纯节点（全关）也合法。
- 能机械验的绝不许模型自报 —— 谁在跑由作业表说、谁该说话由账说，角色由人给。
- 不加上限，把事实说清楚；给养按注意力选，选了什么必须看得见、核得对。
- 手伸出去就是作业：等待是循环的事，不是模型的事（§9）。
- 人不在场，树就在休息 —— 这不是结束。
