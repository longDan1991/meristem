# humanoid：递归工作的 LLM 树

这份文档只写**本质**：为什么长这样、哪些是不变量、哪些只是实现细节。
**不讲进度、不讲计划、不讲"以前怎样、现在怎样"** —— 那些在 `HANDOVER.md`。

---

## 0. 一句话

> **递归消除不确定性，直到剩下不可再分的执行步骤。**
> 上下文下沉是树结构的自然结果，不是机制。
>
> 而这棵树**本身就是成果** —— 它不需要另建一个成果库。

名字叫 **humanoid**：一个会递归拆活、自己动手、把过程留成成果的东西。

---

## 1. 要解决的问题

### 1.1 平铺 agent 的两个死穴

**死穴一：prompt 线性涨。** 会话越长，每一步都要把全部历史重新喂一遍。
实测：一个平铺 agent 的 prompt 从 2,529 tokens 涨到 169,760 tokens
（约 67 倍），而它做的事没有变难。

树的解法不是"更好地压缩历史"，而是**改变历史的归属**：
一个节点只看得见自己的形式字段 + 自己的观测历史。兄弟分支发生的事与它无关。
成本从 `O(总步数)` 变成 `O(这一枝的步数)`。

**死穴二：`P(一次性做对) ≈ 1` 的失败代价。**

大任务一次性做完必然失败，失败重试才是指数级黑洞。
递归拆分把不确定性一路向下消除 —— 每往下走一层，选择空间就小一截，
直到剩下"不需要判断、只需执行"的步骤。

### 1.2 为什么是树，不是 DAG，不是 planner

- 树天然带来**归属**：每一步都属于某一枝，归属决定了它看得见什么。
- 树天然带来**路径**：从根到叶的判据链，就是"这件事为什么值得做"的完整理由。
  这一点后来变成了检索的单位（见 §5）。
- 不做全局 planner：规划需要全局信息，全局信息就是要爆炸的那个东西。
  **拆分即规划** —— 规划分散在每一层的判断里。

## 2. 核心不变量

这八条是这份文档的正文。改代码之前先看它们；如果某次改动违反其中一条，
那不是"实现细节的调整"，是**设计被改了**。

### 2.1 执行树就是成果树

**不另建成果库、不另建记忆、不另建索引。**

节点的形式字段（任务名 / 任务详情 / 验收标准 / 结局 / 结论 / 证据）本身就是索引。

为什么这是不变量：任何"另存一份"的设计都会漂移 ——
存的那份和真实发生的那份必然对不上，而对不上的时候你没法判断哪个是对的。
**让记录就是事实本身。**

推论：老的 trace 不是垃圾，是资产。追溯、检索、挖能力、回归验证，全吃它。

### 2.2 判断自由，动作形式化

> 从心所欲不逾矩。

- **判断**（读事实之后做什么选择）**完全自由**，不给模板、不给评分、不给上限。
- **动作**（任何对世界的改动）**必须经过形式字段**。

**叶子必须能自己看事实、自己决定下一步** —— 它才是那个唯一接触真实世界的人。
把它限制成"只拧螺丝的执行器"，等于让它瞎着干活。

但"自由"必须有一个边界，否则无法机械核对。边界不在**过程**里，在**交付**里：
过程怎么走随你，交出来的东西必须能验。

**一句话：形式化的是格子，不是格子里的字。**
格子要少而固定，格子里的字要给足空间 —— 字数是提示词里的建议，不是代码在管的警察。

### 2.3 能机械验的，绝不许模型自报

**不要相信模型对自己的描述，只相信它对外部世界做了什么。**

实测：让模型自己声明这次拆分属于哪种类型（`kind`），它把自己报成了 69% 的
某种"更高级"的类型 —— 自报字段会被 game。

所以凡是代码能自己看出来的，代码自己看：
- 这步动没动过网络 / 装没装包 / 写了哪些文件 → 从 `bash` 命令**机械抽**
- 这个文件是不是真在磁盘上 → `os.path.exists`
- 子任务的判据有没有丢掉根的可测物理量 → 字符串比对
- 这条证据指不指得到真东西 → 观测下标 / 子节点名 / 磁盘产物

模型只能提供**代码无法自己知道的那部分**：判据、结论、意图。

### 2.4 零计数器

**没有 `max_rounds`、没有 `self_exec_cap`、没有 `depth_cap`、没有 `nudged`。**
轮次 / 深度 / 节点 / token / 时间全部不限。

那"怎么防止它跑飞"？**把事实说清楚，不加上限。**

- 分配节点看 `attempts`（自己试过什么、下层回了什么）
- 叶子看 `observations`（自己做过什么、世界回了什么）

想让它更保守 → 让事实更清楚，不是加一个上限。上限会把"真的需要第 11 步"和
"在死循环"混为一谈，而这两件事的处置方式完全相反。

**唯一的例外是内容信号，不是预算**（见 §2.5 末）：

> 同一动作 + 同一观测，重复 ≥3 次 → 显式告警；≥5 次 → 自己停下，写清原因。

它检测的是**没有新信息**，不是"做得太多"。观测一变（轮询一个正在启动的服务），
条件永远不成立。

**计数必须收口在一个地方。** 任何"把答案退回去让它重来"的路径，都必须经过
同一道计数 —— 一个未计数的重试路径就是一个死循环（依据见 §6）。所以两处收口，
各只有一条出路：

- **动作**的重数收口在调度器的那一处（`_step`）—— 成没成、报不报错，都得过它。
- **"用不了的东西"**（看不懂的输出 / 被拒的分配 / 不合规的结论）收口在 `_balk`。

**人给的上限不在此列。** 上限之所以有害，是因为它把"真的需要第 11 步"和
"在死循环"混为一谈，而这个判断模型做不好；人有全局信息，人能判断。
所以人叫停是合法的 —— 但必须带理由，理由要进记录（见 §2.7、§2.8）。

### 2.5 信息给养：截断必须可见

**这是本项目最贵的一课。静默截断就是对模型撒谎。**

事故现场：一个叶子把同一个文件**读了 25 次**。
原因不是模型傻 —— 是提示词里每条观测只给它看前 200 字，
而且**没告诉它那是截断**。它看到的是断在半句的文件，以为没读全，于是反复重读。

同一类事故的其它形态：
- 先例的判据被砍到 52 字 → 实测 859/2443（35%）的先例判据是残缺的
- 上层只能看到子任务判据的前 80 字，而下限承诺是 140 字
- 观测历史 74%（29/39）超过旧的 200 字上限

**规矩**（注：选项 B 之后，**工具输出不再截断了** —— 见规矩 4。
这条的历史教训仍然有效，但"单次工具输出必须截断"那一条已被压缩取代）：

1. **要么可见，要么别截。**（现在工具输出走"别截"那条；
   read 翻页走"可见"那条。）
   可见 = 写明"还有 N 字 / 还有 M 条" **+ 怎么取回**。
   例：`[/tmp/x.txt 共 7292 字，本段 0-2000] 还有 5292 字未显示 —— read(offset=2000) 取下一段`
   光说"取回"还不够：**取回的路必须真的通**。上面那行写了 `read(offset=2000)`，
   那 `offset` 就必须真的能传下去，否则模型照做了也拿不到下一段。
2. **字数是建议，代码不许偷偷砍，也不许因此而拒绝。**
   "验收标准 ≤140 字"只是给它一个尺度；代码既不切、也不记这笔账。
3. **能不截就别截：总量封顶要去掉。**
   实测词法检索本身很克制（一次命中 7–23 条、1.4K–4.4K 字），
   封顶省下的那点 token，不值得让模型不知道自己少看了东西。
4. **曾经必须截断的地方，现在交给压缩。**
   旧设计里"单次工具输出可能 1GB、观测历史一直涨"所以必须截断 ——
   选项 B（`tree/compression.py`）之后不截了：工具输出完整流到 headroom，
   发送边界无损折叠（JSON 全量保留 / 日志 run-collapse）+ CCR 可逆取回。
   截断会毁掉压缩救不回来的数据（尾部 FATAL 行、超出部分的 JSON），所以没有。
   read 是**翻页**不是截断（本段/还有/怎么取下一段，明说）；
   trace 的 `render_observations` 视图截断只影响调试展示，不是模型收到的。

**递进一层：光摆着历史也不够。**
实测那个叶子，把 31 次观测都摆着，它照样重复。
所以要把**派生的**事实也算出来明说："这个动作你已经做过 5 次，观测完全一样"。
**原始事实 ≠ 结论事实。** 该算的要替它算。

**推论（工具的限制也算信息）：** bash 永远带超时（默认 120 秒 / 上限 3600 秒），
但超时必须**可见、可调、说清后果**：

> [超时] 这条命令跑了 120 秒还没结束，已经被连同它起的子进程一起杀掉。
> 已经产生的输出在上面（不是全部）。要跑更久：把 `args.timeout` 调大（上限 3600 秒），
> 或者 `nohup <cmd> > run.log 2>&1 &` 起在后台再轮询。

三个细节都是同一条纪律：把**已经产生的输出**交回去（一个跑了两分钟才被杀的回测，
前面打印的东西正是它最需要的）；说清"这是超时不是出错"（否则它会当成工具坏了原样重试）；
告诉它怎么跑更久。**一个说得出来的限制不是惩罚，一条不说出来的限制才是。**

### 2.6 形式化的边界：只在结论时、只在入口

- **只在结论时一次**：过程中 `write` 只有 `{path, content}`，不用填任何形式字段。
  结束后一次性交代（判定 / 内容 / 证据 / 工件）。
- **只在入口形式化**：一个多文件程序，只有入口需要完整契约
  （`func` 必须是一条能直接执行的命令），其余文件写 `type="内部"` 就行。

理由：形式化是用来**交付**的，不是用来**工作**的。
在过程中形式化，等于让模型一边干活一边写表格 —— 那会让它把活干成表格。

### 2.7 负知识只能是否证的探针，不能是裁决

**一次失败不是永久否证。** 它证明的是"这条路在**当时**的条件下没走通"，
不是"这条路走不通"。这两句话的处置方式完全相反，分开它们的判据只有一个：
**可不可证伪**。

- 「这个任务做不了」不可证伪 —— 你永远不知道是没试对，还是真不行。
- 「条件 G 当时不成立」可探测 —— 一句 bash 就能在今天重判一次。

所以负知识不许以**任务级裁决**的形式存在，只许以**条件 + 探测方式**的形式存在。

为什么这条必须是不变量：**正能力靠反馈自愈，负能力靠反馈自封。**
一条正能力错了 → 照做 → 失败 → 记账 → 自动退休（§4.3）。
一条负能力错了 → 不尝试 → 没有反证 → **永远不会退休**。
给它剪枝权，就等于掐断唯一能修正它的信息来源。

配套三条：

1. **否决必须带理由，而且理由要枚举。** 禁止的是**无理由**的否决，不是否决。
   "条件变了"和"上次做错了"必须分开：前者不给这条路的信任度加分，
   后者才是能力该学的东西。让人自由写理由，结果必然是"这样不对" ——
   那句话对库里零价值。
2. **时间不能代理"条件变没变"。** 人可能 30 秒内就开了户，也可能三个月没动。
   时间戳只能作**事实显示**（"这条阻塞是 11 分钟前的还是上个月的"），
   判断交回给模型。拿时间窗去排除重复，是又一个裁决，不是事实。
3. **不另建负能力库。** 阻塞的结局字段已经在树上，检索本来就把它带回来
   （§5.3）。另存一份就是 §2.1 说的漂移。

推论：**阻塞不是死路，是待办队列里的一条。**

### 2.8 人是根节点的上层

节点形式字段的规矩是"上层下发，只读"。**人就是根节点的那个上层** ——
不是外挂的操作员，也不是第二个对话者。

1. **不需要一个面对用户的中间 LLM 来指路。** 用户的话要到达树，唯一的风险点是
   "这句话指哪个节点"，而这件事不该交给模型猜。人直接指层。
2. **人的每个动作都是形式化动作，和模型的输入过同一台闸门。**
   加分支要过同一套校验（必填项 / 必须携带父或根的可测物理量 / 最多一个门槛）。
   人不是绕过不变量的后门 —— 否则 §2.1 先从这里烂掉。
3. **人工介入 = 一条带来源标记的外部观测**，走 `observations` 那条已有的通道。
   不发明新机制：`observations` 本来就是"世界回了什么"，人也是世界的一部分。
4. **不重写历史。** 人做的事不修改旧结论，只追加观测，让新的运行得出新结论；
   旧阻塞结论保留，补一条**向后引用**（谁在何时推翻了它、因为什么）。
   **代码不许新旧并存，历史必须新旧并存** —— 它们是不同时刻的不同事实。
5. **模型只能"提议"外部需求，人"确认"。** 自报的"需要人到场"是待确认的推测，
   不是事实。这顺手把 §2.3 的 game 风险消掉了。
6. **LLM 若用在这里，只能当视图，不能当通道。** 视图有损，必须写明是摘要、
   必须能下钻到原始 trace；通道会让人的话被人以外的东西再解释一遍。
7. **入口是这个程序唯一的顶层：谈成一个能过同一台闸门的形式，就当场把树跑掉，
   把结论带回来接着谈。**（`prompts/intake.md` + `tree/intake.py`）
   它不是“常驻的第二个 agent”，也不是“用完即退的提示词” —— 它是唯一入口：
   **谈和跑交替**，直到人在终端上中止。
   纪律：
   - **手在树上，不在入口**：入口自己没有 `bash`/`read`/`write`；它唯一的手是
     `run()` 一棵过了闸门的树。所以它不会变成和树并行的执行者 ——
     它要动手，就必须先交出一个能过校验的形式。
   - **交形式 ≠ 退场，也没有“附加任务”这一说**：每个 `submit_root(root=…)`
     都是任务。跑掉，把结论作为工具结果回填，再调模型。形式能过闸门就拿去跑，
     跑完继续谈 —— 入口自己不停，停是人的事。
     通道与节点同构：模型要么说话（content），要么调 `submit_root` 交形式
     （root 的格子就是 `ChildSpec`，和分配节点写回孩子的是同一套）。
   - **对话的形式不归代码管**：一次问几件事、怎么问、要不要先复述一遍，都是模型的事，
     它是在和真人说话。代码不认识“回合数”，不规定“提问必须带建议”，也不数“同一个问题
     问了几次”（这些曾经都有 —— 全是看模型犯错后婊上去的，后来全删了）。
     代码只认识**出口**。它判断得对的理由只有一条：把“赚大钱”这种话谈成一个
     用户只要点头的写法。
   - **用户不会给你验收标准**：真用户说出来的可能就是“帮我做视频赚钱”。
     把这句话谈成能机械核对的一件事，**是入口的事，不是用户的**；
     问“请给我一个能核对的验收标准”就是把球推回去。
   - **产物过同一台闸门**：缺必填项 / 验收标准里没有可测物理量，当场打回并说清为什么。
     它不可能塞进树检查不了的东西。打回后**把原因摆出来让它自己改**，不拿计数器逼停。
   - **中止不是结论**：用户不再输入就是中止 —— 那时什么都没在跑，也不假装有结论。
     （曾经有个 `blocked` 出口，想让入口替树挡掉“不值得做的事”。删掉的理由：
     判断“做不做得到”要真去撞一次 —— 而入口现在能撞（`run()`），
     那就让树跑出事实，而不是入口提前猜一个。）
   - **对话不用留**：跑出来的东西落在树上（trace / 工作区），而**树就是记忆**。
   - **树实时画给人看**：任务跑的时候，终端把**当前整棵树**实时画出来 ——
     每开/关一个节点就重画一次（真终端用 rich Live 原地重画、非终端逐帧
     追加），跑完留下的最后一帧就是完整结果（视图 `render_tree` 住在
     `fields.py`，和 Node 的其它视图同一边）。过程是人看的，不是只有
     回填给模型的一句摘要。
   - **实时视图每节点一行铺开**：跑的时候终端用 `render_tree(compact=True)` ——
     **每个节点一行**（`· [叶子] 子任务B  ▸ 思考: …`），整棵树按结构铺开，
     所有节点正在吐的字都占一行看得见，谁也不被折掉（屏幕放不下时只折
     没在跑的段落）；根出结论那帧切回详细视图，判定/验收/结论都在。
   - **节点在说什么也实时画出来**：每个节点问模型时的吐字（思考 / 话）按
     node_id 送进树的 Live 帧，画在它自己的节点行上（`run` 的
     `on_delta / on_reasoning` 回调，`turn.ask` 按节点包一层）。
   - **跑任务时输入不冻结**：树的 Live 接管屏幕的同时，终端开一条不渲染的
     prompt_toolkit 会话读键盘（一个屏幕只有一个画家：rich 和 prompt_toolkit
     各画一遍会把光标位置搞乱，实测）。敲下的行进队列，入口下次提问按顺序
     交给它；运行中 Ctrl-D / Ctrl-C 就是中止整个会话。

## 3. 格子的形状

```
Node{ name, detail, notes, accept, kind=dispatch|leaf, gate,
      keywords[], conc_range[min,max], lineage[][],
      attempts[], observations[], precedents[], caps[] }
```

**键是英文，值保持中文。** 模型输出 / trace / 索引 / **模型收到的 user 消息**
共用同一套键：收到的行首就是 `accept:`，它写回去也是 `accept` ——
中间没有"中文标签 → 键"的翻译层可以漂移（"同构"就是这句话，`Node.header`
的 docstring 与 `tests/test_protocol.py` 的 I 段都盯着它）。
中文只留在**给人看**的那一层：树状图、`判定/结论`、以及 `先例` / `现成做法`
这类段落标题（它们不是形式字段，是额外塞给它的旧账）。
字数是提示词里的建议，**代码既不校也不切**。

两个分支，只有两个。模型与程序之间唯一的通道是**三个工具**
（`protocol/tool_specs.py` 的 schema + `runtime/turn.py` 的实现），
每次回复必须且只能调用一个；没调 / 调多个 / 调不在本层列表里的 → 当场打回：

- **分配节点**：`create_children(children=[...])` 或 `conclude(...)`。
  **没有 execute 分支** —— "不拆"就是派一个叶子。少一个分支，少一类边界情况。
- **叶子**：`run_code(code=...)` 或 `conclude(...)`。
  `run_code` 写的是**一段真的 Python 代码**，跑在一个 CPython 子进程里（`runtime/sandbox.py`）：
  三只手 `bash` / `read` / `write` 永远绑着，命中的**现成做法各自绑成同名函数**
  （`runtime/box.py`），`print` 和最后一行表达式的值就是观测。
  **没有 `need`** —— 现成做法在出生时就由程序塞进来了（§4.3、§5.4）；
  运行时还想找就 `search_tools("...")`，命中什么当场装成函数。

`conclude` 两个节点共用：判定 `满足|未满足|阻塞`、正文、证据、external、artifacts（叶子）。
参数形状由 pydantic schema 强制（`protocol/tool_specs.py`，经 FastMCP 注册，
本地/远端同构）；**语义校验仍走 gate**（`clean_spec` / `clean_conclusion`），
拒绝信息保持中文原文。字段的"本质"说明在 schema 的 description 里
（provider 会原样喂给模型），`prompts/*.md` 只剩流程与长规则。

每个子任务**除 `notes` 外全部必填**，缺一个当场被拒：
`name` / `detail` / `accept` / `kind` / `keywords` / `conc_range`。
`kind` 不给兜底：写错（或没写）就是这次分配不成立，不默认成 dispatch ——
提示词里那句 `"kind":"dispatch|leaf"` 是给**人**看的枚举示意，不是合法取值。
`notes` 选填、不限字数、而且**不参与检索**（自由发挥的判断依据放进词法匹配只会污染召回）。

三个由代码把关的硬性要求：

1. **子任务的验收标准必须携带父/根的可测物理量**（日期、两位以上数字、标识符）。
   否则这次分配当场被拒。防的是"把任务悄悄换成别的东西" ——
   实测锚点在深度 1 就被换成了 `{close,date,high,low,open,volume}`。
2. **判定"满足"必须指得出真证据**，否则降级为"未满足"。
3. **产出的每个文件都要交代**，`func` 必须是能直接执行的命令。

**门槛（轻重缓急）**：一次分配最多一个门槛，它先做，不成立则整个分支作废、
兄弟永不启动。想不出作废条件就别标 —— 想不出说明这事没有真正的前提。

每个字段在提示词里都附了**它的本质**，因为想清楚在判断什么比填对格式重要：
`name`=归属、`detail`=上下文、`accept`=可机械核对、`kind`=分工、
`keywords`=不浪费已经做过的工作、`conc_range`=想要的成果规模、`gate`=轻重缓急。

**注入面是公开的**：`render()` 会渲哪几段（先例 / 现成做法 / 上层意图链 /
本层已有尝试 / 观测历史 / 手上的东西），`prompts/*.md` 里逐段点名，
`tests/test_protocol.py` 的 I 段**双向核对**：文档说了没渲 = 承诺落空，
渲了文档没说 = 偷偷塞东西。（旧账：叶子那份曾经写了"命中的判据链在先例里"，
而叶子根本不渲先例 —— 这个核对就是为了让这类漂移当场红。）
形式字段那几行不做截断、不做替换，行首就是字段名；哪一行是谁给的
（上层填的 / 程序查出来的）写在 `prompts/*.md` 里。
提示词文件是 **system**，被注入的那几行在**另一条 user 消息**里（`turn.ask`）。

`lineage` 是唯一一个**不是上层下发**的形式字段：节点出生时由 `scheduler._spawn`
从父节点拼出"从根到上层"的 `[[name, detail], …]`，**两种节点都渲染**。
没有它，节点只知道"我要干什么"，拆到第三层就没人记得最初的验收标准是给谁用的。
它物化在出生时、不在 render 时反查 registry —— 形式字段只读，父的 detail
出生后不会再变，所以物化不会变旧（§11）。

## 4. 能力：从成功里长出来

### 4.0 能力库就是盒子：注册 / 搜索 / 调用

叶子不是“拄一条命令去 bash 里跑”，而是**写一段代码去调函数**。
能力库（`memory/caps.py`）是那个装着所有工具的盒子，三个动作对应三件事
（`runtime/box.py`）：

| 动作 | 谁调 | 干什么 |
|---|---|---|
| `register(entry)` | `scheduler.settle` → `learn` | 节点完工，把这次成功的做法（+ 契约）写进库 |
| `search(query)` | 节点出生（`register`）、运行时 `search_tools()` | 命中什么就返回什么：文字给**全部**命中，函数只绑**有签名**的那些 |
| `call(tool_id, args)` | 子进程里的同名函数 | 填模板 → 跑 → 记 uses/fails |

**“有签名”就是契约里有 `func`**（`func` 里 `__名字__` 是占位符，`params` 说它
是什么类型）。只有这种能变成函数；只有配方、没签名的仍在文字里，能照抄着跑。
错签名比没签名更坏 —— 它会把模型引到一条走不通的路上（`gate.contract_problems`
在结论那一刻就把对不上占位符的 params 退回去）。

**叶子写的那段代码跑在一个真的 CPython 子进程里**（`runtime/sandbox.py`），
不是沙箱：叶子本来就有 bash，给编排代码加沙箱等于给已经握着钥匙的人装防盗门，
代价却是那套 Python 子集（没有 pandas / glob / async with）。协议是一行一个 JSON：
子进程要调工具就写一行到 stdout 等回答，它的 `stderr` 整份就是**观测**。

两件必须刻意的：

- **超时在子进程里触发**（SIGALRM），所以 `while True: pass` 能被中断，
  而且“超时”是一条**观测**（和 bash 一样明说），不是静默杀掉。
  等宿主的时间不计入额度 —— 一条跑 20 分钟的 bash 不该吃掉代码的额度。
- **产出记账靠跑前跑后 diff 工作区**，不是解析工具参数：代码模式下没有参数
  可解析，而 diff 连 `open()` 直接写的文件都跑不掉，比解析参数硬。

### 4.1 一个工件一条能力

能力的来源不是"人灌进去的配方库"，是**节点真的做成功过**这件事本身。

- 节点完工 → 从它的动作历史里长出能力（在线增量）
- 进程被 kill → 事后从 trace 补挖（离线批量）
- 同一套提取逻辑，两条路共用

**规范能力来自契约**：结论里交代的那个入口工件（带 `func`/`args`/`return`）。
单纯"跑一个已经存在的契约工件"的 bash 动作不再记第二条 ——
否则同一件事会有很多条平行版本，能力库立刻退化成噪音。

**只有能跑起来的工件才算能力。** 数据、配置可以有契约、有 sidecar，但不进库。

**名字要继承，不要发明。** 契约里的 `name`（当初写它的用途）应该进中文桥。
自己编的名字（"执行 account_query_evidence date query_meta txt http"）没有任何价值。

### 4.2 死路也值钱

成功和失败**同价**：实测成功分支 21,054 tokens、失败分支 20,843 tokens。

所以成果树里有两样东西：

- **能这么做的**（可实现的做法）
- **卡在哪儿的**（这条路当时因为条件 G 没走通，卡在哪条命令上）

第二样**不需要另建一层**（§2.7）：它就在节点的 `判定` + `结论` + `外部需求` 里，
检索本来就沿判据链把它带回来（§5.3）。另存一份就是 §2.1 说的漂移。

**但前提是把它渲出来**：一条阻塞先例如果只带回一句"做不了"，模型只能照抄；
把 `外部需求` + `证据` + **卡在哪条命令、当时世界回了什么**跟着路径一起带回去，
它才能自己重判一次。前者是断言，后者是探针 —— 差别就在这几个字段上。

⚠️ **不要把"阻塞"和"死路"当同义词。** 实测全语料里**一条结论级的阻塞记录都没有**，
而一晚上 2443 个节点里 86% 只是被 kill 在半路。拿"没跑完"当"此路不通"去挖，
一晚能写出两千条假死路。

### 4.3 复用失败要能自动修正

现成做法在节点出生时就按 `keywords` 注入（§5.4）。它一旦被真的跑起来，
代码机械核对这次成不成（不靠模型自报）：失败累计 → 自动退休。成功 → 记账 + 学会。

这是"检索偏召回"敢成立的前提：**召回可以不准，因为精度有反馈兜底。**

## 5. 检索：单位是路径

### 5.1 检索的错配

用"文本像不像"去代理"能不能用"是错配。实测的噪音：

> 查询"回测 扣费后 正期望" → 命中了"从任务配置或上下文中获取**期望**余额A的具体数值"

这不是 bug，是词法匹配的极限。

### 5.2 出路

1. **检索偏召回**：宁可多给，不肯漏给。精度不靠检索保证。
2. **精度交给反馈**：`cap_outcome` 记账 + 失败自动退休。
3. **语义判断交给模型一次**：给它看，它自己判。它擅长这个。
4. **键用可执行形状**：包名、命令动词、数字、脚本名 —— 而不是形容词。
5. **参数由模型自己定，而且是一组**：它用不同的说法、从不同侧面问同一次，
   程序一次扫遍所有老树。实测模型自己给出了很好的三组查询：
   `["2026-12-31 权益翻倍 的判据", "A股 量化系统 回测 扣费后正期望", "开户 入金 实盘 真实账户 权益"]`

### 5.3 返回的是路径，不是节点

一个散落的节点没有意义。有意义的是**从根到它的那条判据链** ——
它顺带解释了"这件事为什么值得做"，并且带着它当年的**工作目录**。

工作目录有个使用上的约束：**只有在它等于当前 cwd 时才渲染成"工作目录"**。
不同的只能说"先例的数据在: …（只读）"。写成一个裸的"工作目录: …"，
模型会把它抄进子任务详情、当成自己的 cwd，产出就落到那棵老树里去了
（实测发生了一次）。工作区选哪个是启动时的事（`main.py`），不是提示词里的事。

同一脉只留分最高的那条，否则三条先例可能是同一件事。

**结局即质量信号**：满足的先例可以照抄计划；阻塞的先例要把**卡在哪条命令、
当时世界回了什么**一起带回来（§2.7）—— 它不扣分、不过滤，因为它是"上次卡住的地方"，
不是"这条路不行"。

### 5.4 出生时自动检索一次，键是**上层给的**

实测：让模型自己决定"要不要看历史"太弱 ——
小任务它不查（对的），**但大事它也可能不查**，而真正贵的恰恰是大事。

所以检索不是模型的一个动作，而是**出生时发生的一件事**：

- 每个子任务必须带 `keywords`。**它的本质是不浪费已经做过的工作。**
- **分配节点**一出生，程序就拿这组键扫**所有老树 + 能力库**，把命中的判据链和
  现成做法直接塞进它的提示词。
- **叶子只查能力库**：先例回答的是"这件事该怎么拆、当年卡在哪" —— 拆是分配
  节点的事，叶子要的是工具。老树对叶子只是噪音（实测：叶子的价值全在工具上）。
- 根没有上层，就用它自己的任务名 + 验收标准查一次。

**模型没有理由主动去查**（它觉得自己都会），所以这件事不该交给它决定 ——
`先例` 和 `need` 都不是动作。检索不花 LLM 调用。

### 5.5 跨树只有引用，没有继承

老树不是一段可以"接着跑"的进度 —— 它是一批"已经做完 / 已经卡住"的记账。
树没有挂起状态可以恢复（要么出了结论，要么被 kill）。所以"复活老树"是个假选项：
能复活的不是进程，是**证据**。

于是"新消息和老树很像，该复活还是新建"变成一个机械问题：**哪些证据今天还指得动。**

| 老结论 | 处置 |
|---|---|
| 满足，证据是磁盘产物 | 产物还在 → 不派节点，直接引用 |
| 满足，证据是"第 N 次观测" | 观测属于那棵树，跨树指不动 → 要么已落盘，要么重做 |
| 阻塞（因为 G 不成立） | 重做，但先探一次 G（门槛，§3） |
| 没结论（被 kill） | 重做 |

1. **只有一个机制：新建节点，决定搬几条老账。** "复活"是搬全部，"完全新建"是搬零条 ——
   它们不是三个选项，是同一条刻度上的两个端点。
2. **复用发生在分配那一刻，逐条判，不预切树。** "复活一半"若理解成
   "从某个节点开始恢复下半棵树"，就必须决定从哪儿切 —— 那又是猜。
3. **关系是引用，不是父子。** 老树永远不会再给新树一个结论，所以它不是父；
   新树某节点的证据字段指向 `runs/xxx#node`。**引用不改变结构** ——
   谁是谁的父，仍然只有一条链（§1.2）。
4. **判据不能用"像"。** 像不像只是召回手段（§5.2）。像但证据过期 → 重做；
   不像但那件产物还在 → 照样能用。拿"像"当决策依据，就是 §5.1 那个错配。

## 6. 实测依据

每条不变量背后都对应一次事故或一个数字。别把它们当修辞。

| 要解决的问题 | 数字 |
|---|---|
| 平铺 agent 的 prompt 线性涨 | 2,529 → 169,760 tokens |
| 一次性做对大任务必然失败 | 一晚 2443 节点 / 8648 调用 / 35.7M tokens / 11.5h，**86% 节点从未完工** |
| 递归不是指数爆炸 | 扇出从 3.0 衰减到 1.1（饱和级联） |
| 判据会漂移 | 只有 3% 的根以下判据提到"钱"；锚点在深度 1 就被换成 `{close,date,high,low,open,volume}` |
| 失败和成功同价 | 20,843 vs 21,054 tokens |
| 自报字段会被 game | 自报 `kind` 被 game 到 69% |
| 静默截断会引发重读 | 一个叶子把同一文件读了 **25 次**；74% 观测超过旧的 200 字上限；35% 先例判据曾被砍成残句 |
| 光有索引能省多少 | 同一个量化任务：11.5h/2443 节点/3570 万 tokens → **4.3 分钟/2 节点/3 万 tokens**，结论从"没有结论"变成"阻塞 + 原因 + 引用先例" |
| 把"阻塞"当"死路"会写出一堆假死路 | 全语料结论级阻塞 **0 条**；`外部需求` 真进 payload **0 条**（16 处命中全是提示词回显）。且 2443 节点里 343 完成 / 28 崩溃 → **86% 无结局** |
| 浪费的主体不是"重撞死路" | 同一 `(工具,参数)` 重复 ≥3 次共 **456 次**调用，榜首是 `pwd && ls -la`（98 次）、`ls -la`（74 次）—— "不知道自己站在哪里" |
| 时间戳不用新加 | trace **每一行**都已有 `t`，精度到毫秒（如 `1789568177.102`） |
| 未计数的重试路径 = 死循环 | 实测撞到两次：看不懂的输出（同一回合不停）、同一份被拒的拆法。两种情况都没有动作，所以"重复动作"那个信号永远不触发 |
| 阻塞的理由会自己翻转 | 一次真实阻塞结论的 3 条理由里，有 2 条会随时间/人为动作自己翻转（"日期尚未到来"、"需要人到场"）—— 所以负知识只能存成条件 + 探针 |

## 7. 设计的边界（取舍与代价）

- **检索是词法的。** 见 §5.1 —— 同义/近义只能靠模型判断，这是选择"偏召回"的代价。
- **观测历史有可见预算。** 单条 1500 字 / 最近 10 次 / 总 6000 字。
  这是**必须截断**的地方（不截跑不起来），数值是拍的，不是算出来的。
- **无进展检测的阈值 3 / 5 是拍的。**
- **`conc_range` 只是建议，代码不校。** 上下层给的值只进提示词；
  没有人把关"是不是真按规模写的"。
- **检索键的质量全靠模型。** `keywords` 写歪了，注入的先例就是噪音 ——
  好在偏召回 + 反馈能兜底（§4.3、§5.2）。
- **跨树的引用只走一步。** 引用链不递归追溯：A 引用 B，B 又引用了 C，
  看 A 的时候不会自动看到 C。

## 附：一句话回顾

- 树不是为了好看，是为了让**成本跟着这一枝走**，而不是跟着总步数走。
- 形式化不是为了管住模型，是为了**让成果能被验、能被检索、能被复用**。
- 不加上限，因为上限会把"真的需要"和"在死循环"混为一谈。
- 不偷偷截断，因为它会让模型**瞎着干活，而且不知道自己瞎**。
- 执行树就是成果树 —— **记录就是事实本身**。
- 负知识只能是否证的探针 —— **一次失败不是永久否证**。
- 老树能复用的不是进度，是**证据**。
- 人不是外挂的操作员，是**根节点的上层**。
- 检索不是模型的一个动作，是**出生时发生的一件事** —— 键由上层给，
  老树给分配节点看（"这该怎么拆"），能力库所有节点都看（"拿什么做"）。
- 任何"退回去重来"的路径都必须计数：**一个没计数的重试路径就是死循环**。
