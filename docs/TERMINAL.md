# 终端布局：树 + 并行会话流（设计）

> 这份文档只写**本质**：终端长什么样、哪些是不变量。
> 进度与交接在 `HANDOVER.md`；系统提示词的设计（另一份本质）在 `PROMPTS.md`。

---

## 0. 一句话

> **左树右流：左栏是整场会话的树（地图），右栏是选中节点的消息流（滚动日志）——**
> 思考、对话、工具执行全在这一个流里，**树选中谁，流就切到谁的对话**；
> 底部一条拉通全宽的输入行，跑任务时也活着。

---

## 1. 布局（一屏，无模式切换）

```
┌─ 会话树（地图）──────────┬─ 流（选中节点的消息，滚动）───────┐
│ ✓ [入口] 会话            │ 你: 把数据处理干净               │
│ └─ ✓ [分配] 搭建管线    │ 入口: 验收标准？                 │
│    ├─ ✓ [叶子] 扫描输入 │ 你: 产出 clean.csv 就算          │
│    ├─ · [叶子] 归一化   │ 入口: 好，拆 3 个子任务，开跑     │
│    └─ ⏳ [分配] 训练    │  · 思考: 用 pandas 读…            │
│       └─ – [叶子] 标注  │  · 说: 我先看 schema             │
│                         │  · 工具: bash ls -la (0.3s)      │
│                         │ …（↑/↓ 普通滚动，默认贴底跟随）   │
├─────────────────────────┴──────────────────────────────────┤
│ 6 在飞 · 23 节点 · 4.2s（状态条，拉通）                      │
│ › 输入（拉通全宽，跑的时候也活着，敲的行排队交给入口）       │
└─────────────────────────────────────────────────────────────┘
```

五个区，固定位置，不随跑/谈切换：

| 区 | 职责 |
|---|---|
| 左栏 · 树 | 整场会话的地图：入口根 → 所有任务根 → 子树，可折叠，带状态标记；整场的并行状态由它呈现 |
| 右栏 · 流 | 唯一频道：选中节点的消息流（思考 / 对话 / 工具执行全在这） |
| 状态条 | 在飞 n/6、活跃节点数、时长、滚动状态（如「↑ 已上翻」） |
| 输入行 | 常驻、拉通全宽；跑任务时照样能敲，敲的行排队交给入口 |

---

## 2. 流：一个日志，树决定作用域

- **流 = 选中节点的消息流**：它自己 `msgs` 里有什么就显示什么
  （`user` / `assistant` / `tool` 按序），实时尾巴附加在底部。
- **入口根与其它节点同构**：选中入口根，流里就是这场对话。没有"整场聚合流"——
  整场的并行状态由左栏树的状态标记呈现，要看哪个节点，就切到哪个频道。
  树是频道选择器，流是唯一频道。
- **流是"活的"**：message_update 一 token 一发，终端合帧 ≈30fps 重画——选中节点的
  思考 / 说话 / 工具调用实时流出来；整段话提交进对话后，重画由 `ask` 起帧
  （入口）或后续事件（任务节点）触发，从不留陈旧帧。
- 节点出结论时，流里补一行结论标记（判定 + 验收标准）——结论是过程的终点，
  和思考、说话、工具一样是"发生的事"，不另开窗格。

## 3. 滚动

- 普通滚动：滚轮 / PgUp / PgDn，不冻结、不翻页翻块。
- 默认贴底跟随新消息；上翻即停跟，状态条显示「↑ 已上翻」；按 End 回底跟随。
- 行超宽不静默截断（§坑 1：静默截断是最大的教训）——宽行换行显示或横向滚动，
  具体形态是实现细节，但"看不见"不允许。

## 4. 行的渲染（rich renderable）

渲染引擎是 **rich**（Markdown / Panel / 彩色 Text），经 ANSI 桥进 prompt_toolkit 帧：

- `user` / `任务` 消息 = **加粗**一行（`你: …` / `任务: …`）。
- `assistant` 内容 = **Markdown**（标题 / 列表 / 行内代码 / 代码块高亮）。
- 思考（reasoning） = **蓝斜体**一行（区别于说话正文与工具青）。思考随消息进
  对话历史（`Message.reasoning` → dialogue 落账），随消息渲染、续跑也在。
- 工具调用 = **青色**一行（`工具: 名(参数)`）；工具输出 = **Panel 框**（title=工具名，
  与聊天内容分开，全文不截断）。
- 判定 = 绿（满足）/ 红（其它）。
- 树上的状态标记：`·` 运行中 / `✓` 满足 / `✗` 未满足 / `⏳` 阻塞 / `–` 未启动。

> 不引入专门的"AI chat TUI 组件库"（调研：没有成熟产品；Textual 是最接近的完整框架，
> 换它 = 输入行为回归 + 测试基建重写）。rich 就是组件库——它的 renderable 体系
> （Markdown / Panel / Text）覆盖聊天组件需要的全部，`Console(color_system="standard")`
> 渲成 ANSI 后由 `prompt_toolkit.formatted_text.ANSI` 转片段上屏。

## 5. 树（地图）的折叠规则

- **只展开正在动的东西**：跑完的子树折成一行带统计
  （`✓ [分配] 管线 12 节点 3.2s`），活跃路径自动展开。
- 折叠是展示的变因，住终端层；树的结构与判定是协议的事实，终端只读不改。

## 6. runtime 必须供给的事实（事件词汇）

终端要画出上面的流，只发 `loop_start` / `loop_end` / `message_update` 不够——以下事实
loop 现在就知道（工具 gather、`_log_usage`、busy 集合），但没发：

| 事实 | 现状 | 要补 |
|---|---|---|
| 工具开始 / 结束（工具名、耗时） | 不发，终端对工具过程是黑盒 | `tool_start` / `tool_end` |
| 每次调用的 token 用量 | 只写 trace | `usage`（prompt / completion） |
| 节点在等什么（LLM / 工具 / 用户） | 终端只能猜 | 由上述事件可推导，不另设状态事件 |

事件只报事实、怎么画是终端的事（`EventSink` 机制不变，词汇随消费者需求长）。
**终端与 runtime 的唯一契约是事件**：终端不读 store / trace（`throttle` 落盘在跑，
读会撞上未落盘的缓冲，而且边界就乱了）。

## 7. 不变量（改代码前看）

1. **一屏固定五区**：树 / 流 / 状态条 / 输入行；无模式切换，跑与谈同屏。
2. **树是频道选择器**：流的内容 = 选中节点的消息流（入口根与其它节点同构，
   选中它看到的就是这场对话）。
3. **思考 / 对话 / 工具执行都进同一个流**：不分区、不交错丢信息。
4. **输入常驻**：跑任务时输入不冻结（既有行为不变量，布局不破坏它）。
5. **终端只画事实**：事件词汇是 runtime 与终端的唯一契约。
6. **树的展示变因住终端层**：折叠 / 标记 / 颜色不改协议字段序列化。

## 8. 不做的事（YAGNI 边界）

- **不另开"前沿窗格 / 焦点窗格"**：流一个就够，并行与深度都靠"树切流"这一个机制。
- **不做整场聚合流**：入口根就是一个普通节点，流 = 选中节点的 `msgs`，不为"整场"
  另造一条消息序列（那需要给 msgs 加时间戳或读 trace，都违背 §6）。
- **不做 F 跟随键**：主线先不做，树选中切频道是唯一导航。
- **不做模式切换**：不搞"谈阶段 / 跑阶段"两套界面。
- **终端不读 store / trace**：要什么事实，让 runtime 发事件。
