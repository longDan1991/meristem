# 终端布局：一块 Textual 应用（树 + 选中节点流 + 实时尾巴）

> 这份文档只写**本质**：终端长什么样、哪些是不变量。
> 系统提示词的设计（另一份本质）在 `PROMPTS.md`。

---

## 0. 一句话

> **一块 Textual 应用占满整屏**：日志区（选中节点的消息流，应用内滚动）+ 实时尾巴 +
> 树条带 + 状态条 + 输入行。**屏归应用**，所以"切频道重绘"只是 widget 操作
> （清日志区再写回去）—— 不写裸 ANSI、不需要猜"我上一帧画了几行"，也不会有第二个
> 渲染器跟它抢同一块屏。
> 树是频道选择器：**↑↓ 切选中节点 → 日志区重画成它的完整消息流**。
> **焦点永远在输入行**：Enter 提交、Alt-Enter 换行、Ctrl-P / Ctrl-N 翻输入历史、
> Ctrl-T 收/展树条带、Ctrl-F 展开/折叠选中节点、**Ctrl-Q / Ctrl-C 收手**（不看输入行里有什么）。

---

## 1. 布局（一屏，无模式切换）

```
你: 把数据处理干净                                        ← 日志区（应用内滚动）
入口: 验收标准？
你: 产出 clean.csv 就算
入口: 好，拆 3 个子任务，开跑                              ← 有节点在跑时状态条写"n 运行中"
思考: 用 pandas 读…                                       ← 灰斜体（已提交的历史行）
我建议写成：**账户权益 >= 本金 x 2**                        ← Markdown（提交后整段落地）
工具: bash({"command": "ls -la"})                        ← 工具行青色（参数超宽交给组件换行）
工具结束: bash (0.3s)
思考: 第二步要先把 schema 定下来……                        ← 实时尾巴（未提交，最多 8 行）
└─ ✓ [分配] 管线 12 节点 3.2s                             ← 树条带（地图，默认展开）
   └─ · [叶子] 归一化  ◀ 选中（部件画的选中底色）            ←   Ctrl-T 收起
选中 归一化 · 6 运行中 · 23 节点 · 4.2s                    ← 状态条
› 输入（拉通全宽，跑的时候也活着，敲的行排队交给入口）       ← 输入行
```

五区：

| 区 | 职责 |
|---|---|
| 日志区（`#log`，`VerticalScroll`，1fr） | 选中节点**已提交**的消息流：`store.dialogue(nid)` 里有什么就按序挂什么（user / assistant / tool）+ 判定行，**一条消息一个 Textual 组件**。滚动与换行是它自己的（应用内滚动）；**不画滚动条**（`scrollbar-size: 0 0`，内容占满整宽才像原生终端；滚轮 / PageUp 照旧滚） |
| 尾巴区（`#tail`，≤8 行） | 选中节点**还没提交**的那一小段实时文字：思考灰斜体、说话纯文本。提交就清空，空着不占行；涨过上限自己滚（看的永远是**最新**那几行） |
| 树条带（`#tree`，6 行） | 整场会话的地图：入口根 → 所有任务根 → 子树，可折叠，带状态标记；默认展开，Ctrl-T 收起。↑↓ 选中节点（选中即换频道）—— 一棵 `OptionList`：高亮与滚动都是部件自己的 |
| 状态条（`#status`，1 行） | 选中节点 · 未出结论的节点数（`n 运行中`） · 节点总数 · 时长 · token 数 · 等你回答 · **收手键（`Ctrl-Q/C 收手`，常显：退出的路不能只在输入行空着时才看得见）** |
| 输入行（`#input`，TextArea） | 常驻、拉通全宽、随内容长高（最多 8 行）；跑任务时照样能敲，敲的行排队交给入口 |

五区**左右各留一列边距**（`#log, #tail, #tree, #status, #input { padding: 0 1; }`）：字不贴屏幕边 —— 这是输入行一直以来的边距，现在推广到全屏，五区的文字从同一列起。边距是 widget 的 padding，内容区因此窄两列（`content_region.width = 终端宽 - 2`），日志区与尾巴的换行照这个宽度走。

## 2. 流：选中节点的消息 + 它自己的实时尾巴

- **流 = 选中节点的消息流**：它自己 `msgs` 里有什么就显示什么（`user` / `assistant` /
  `tool` 按序），末尾接判定行。入口根与其它节点同构：选中入口根，日志区就是这场对话。
- **切节点 = 日志区清掉重画**：↑↓ 换选中节点时 `remove_children()` + 把该节点的完整消息流
  挂回去 + 挂上它的实时尾巴。清的是应用自己的 widget，屏上历史就是这一区的滚动内容。
- **实时尾巴是另一块**：思考灰色逐字吐（进尾巴区、不逐字排版）；说话先缓冲，
  **提交后以 Markdown 整段落地**（最终输出才 Markdown）。尾巴区只装"还没进 store 的
  那一小段"。
- **提交 = 消息进了 `store`**：`store.append_assistant` 一发生，这一段就算落地。
  落地时机就是那几个事件——LLM 调用结束后紧跟着的 `tool_start` / 入口提问（`ask`）/
  `loop_end`。落地后从 store 重画（切频道回来）与 live 写进去的是同一份内容，
  不会出现"重画少一段 / 多一段"。
- **日志区只画选中节点这一个频道**：别的节点的流式与工具事件不写进来（免得串台），
  它跑它的，树条带（`·` 标记）与状态条（`n 运行中`）看得见；切过去就能看到它完整的
  流 + 它的实时尾巴（尾巴按节点存着）。落到别的频道的尾巴不算丢内容：提交意味着
  消息在 store 里，切过去重画时整段都在。

## 3. 为什么屏归应用（旧方案为什么不成立）

旧方案是"日志进正常缓冲（终端 scrollback）+ 底部 prompt_toolkit 提示区 + 切频道
`\x1b[2J` 清屏重印"。它不成立，原因是**两个渲染器抢同一块屏**：

- rich 手写的裸 ANSI 与 prompt_toolkit 的渲染器互相不知道对方的屏状态，光标记账必然
  错位（所以旧代码得靠"猜面板有几行、补几个空行"糊住）。
- `\x1b[2J` 擦掉的是**当前屏**那一截，不是推进 scrollback —— 屏上还没滚出去的对话
  （包括用户刚敲的）直接没了；而重印出去的内容随日志增长又会滚进 scrollback，
  于是 scrollback 里堆的是"同一段话的 N 份快照"，不是时间线。
- 根子上，"清屏重绘"与"scrollback 就是历史"只能留一个：清屏必丢屏上的东西，
  重印必往 scrollback 灌副本。

现在选**屏归应用**：Textual 进备用屏，差分重绘（`ScreenDiff`）与擦除是它渲染器的活，
应用层只改 widget。代价说清楚：终端 scrollback 不再承载会话历史（退出应用后终端恢复
原样，会话历史不留痕），历史改在日志区里滚 —— 滚轮 / PgUp / PgDn 由 Textual 的
`ScrollView` 处理，复制/选择也走 Textual 自己那套。

## 4. 行 / 渲染（Textual 组件 + CSS 类）

日志区与尾巴区都由 **Textual 组件**组成，样式一律走 CSS 类（`view.ROW_CSS`，应用并进
自己的样式表）—— 排版与框线是组件的本职，终端层只挑组件、给文本、贴类名：

- `user` / `任务` 消息 = **加粗**一行（`你: …` / `任务: …`，`Static` + `.msg-user`）。
- `assistant` 内容 = **Markdown 组件**（标题 / 列表 / 行内代码 / 代码块高亮）——
  **最终输出**才走 Markdown（逐字流式片段没法排版，所以说话提交后整段落地）。
- 思考（reasoning） = **灰斜体**（`.msg-think` / `.tail-think`）：未提交时在尾巴区逐字吐，
  提交后作为历史行留在日志区。
- 工具调用 = **青色**一行（`.msg-tool`，`工具: 名(参数)`，参数是模型发来的 JSON）；
  工具结束一行带耗时；工具输出 = **`Collapsible` 框**（title=工具名，可折，与聊天内容
  分开，全文不截断）。
  `工具结束` 那一行只出现在**实时**屏上：耗时没进 store，切频道重画时只有工具调用行
  与输出框 —— 实时多一行、重画少一行，两边都不编造。
- 判定 = 绿（`verdict-ok`）/ 红（`verdict-bad`）。
- 树条带上的状态标记：`·` 运行中 / `✓` 满足 / `✗` 未满足 / `⏳` 阻塞 / `–` 未启动；
  选中行的高亮底色是 `OptionList` 自己画的（`option-list--option-highlighted`）。

> 超宽不静默截断（§坑 1：静默截断是最大的教训）：参数与长内容都交给组件换行显示。

## 5. 树（地图）的折叠规则

- **只展开正在动的东西**：跑完的子树折成一行带统计
  （`✓ [分配] 管线 12 节点 3.2s`），活跃路径自动展开。
- 折叠是展示的变因，住终端层；树的结构与判定是协议的事实，终端只读不改。

## 6. runtime 必须供给的事实（事件词汇）

终端要画出上面的日志区、尾巴与条带，只发 `loop_start` / `loop_end` / `message_update`
不够。事件只报事实、怎么画是终端的事（词汇随消费者需求长）：

| 事实 | 事件 | 载荷 |
|---|---|---|
| 节点开跑 / 出结论 | `loop_start` / `loop_end` | `node` |
| 流式增量（说话 / 思考分开） | `message_update` | `kind`（`content` / `reasoning`）+ `delta` |
| 工具开始 / 结束 | `tool_start` / `tool_end` | `name` + `arguments`（开始）、`name` + `secs`（结束） |
| 每次调用的 token 用量 | `usage` | `prompt` / `completion` / `reasoning` / `cached` / `total` |

都带 `scope=节点 id`。**终端与 runtime 的唯一契约是事件**：终端不读落盘文件
（trace / 记录文件，`throttle` 落盘在跑，读会撞上未落盘的缓冲）；`store.dialogue(nid)`
是同一进程的内存账本（切频道重画读它），不算读文件。

## 7. 不变量（改代码前看）

1. **屏归应用**：所有上屏都走 Textual 的 widget / renderable，**不写裸 ANSI 控制码**
   （清屏、光标、擦行）。
2. **日志区是一个频道**：↑↓ 切选中节点 → 清日志区重画该节点的已提交消息；
   不做"整场聚合流"。
3. **提交才落地**：未提交的文字只在尾巴区；提交 = 消息进了 `store`，落地时机见 §2。
4. **最终输出才 Markdown**：说话提交后整段落地为 Markdown；思考灰斜体。
5. **焦点永远在输入行**：↑↓ 切树节点（历史让位 Ctrl-P/Ctrl-N）、Enter 提交、
   Alt-Enter 换行、Ctrl-T 收/展树条带、Ctrl-F 展开/折叠选中节点、**Ctrl-Q / Ctrl-C 收手**
   （都不看输入行里有什么 —— 退路不能依赖输入行的状态）。Ctrl-D 不占（和终端习惯冲突），
   归输入行自己的删字符。所以状态条上一直写着 Ctrl-Q/C。
6. **输入常驻**：跑任务时输入不冻结，敲的行排队交给入口（ask 按序取）。
7. **终端只画事实**：事件词汇是 runtime 与终端的唯一契约（§6）。
8. **视图层只产 Textual 组件**：`view.py` 挑组件、给文本、贴类名（CSS 也在它这里），
   不管组件谁挂上去；rich / prompt_toolkit 不是本项目的依赖。
9. **树的展示变因住终端层**：折叠 / 标记 / 颜色不改协议字段序列化。
10. **一个介质一套输入**：真终端（tty）里输入只有一块屏上的输入行；非真终端（管道 /
    重定向）按行读 stdin —— 不另开第二个渲染器、不自己画键位。

## 8. 不做的事（YAGNI 边界）

- **不做整场聚合流**：入口根就是一个普通节点，流 = 选中节点的 `msgs`，不为"整场"
  另造一条消息序列（那需要给 msgs 加时间戳或读 trace，都违背 §6）。
- **树条带不换成 `Tree` 部件**：折叠规则（`render_folded`）必须同时给非真终端那条路产
  **文本帧**（管道里没有屏可占、没有部件可挂），所以它先产 `[(node_id, 行)]`，真终端这侧
  再交给 `OptionList` 挂出来（高亮 / 滚动 / 滚轮是部件的）。换成 `Tree` 会让"折成一行带
  统计"这套规则出现两份。
- **不自己接鼠标**：鼠标留给组件（滚日志区、选文字、点一下条带换频道、点工具框标题折叠
  都是它们自己的行为）；不做"滚轮切条带"这类自己写的鼠标逻辑。
- **不做模式切换**：不搞"谈阶段 / 跑阶段"两套界面。
- **终端不读落盘文件**：要什么事实，让 runtime 发事件。

## 9. 实现落点（设计住在哪）

| 设计元素 | 代码 |

| `-r` 的会话选择器（Textual `OptionList`） | `terminal/picker.py` |
