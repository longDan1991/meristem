# 我们的原型 · P0（总体规划 · 骨架九节）

> **这一份定产品的骨架**：**有哪几屏** · **全局布局** · **内容区三档** · **侧边** · 屏与档之间**怎么切** · **跨档跨屏的全局规则** —— 一节一份，改哪节动哪节（见下表）。
> **写法**：**始终以用户故事为主线** —— 每一处都从"我做了什么、屏幕上出来什么、之后我在哪"讲。不写成模块清单，也不写成功能目录。
> **每一屏内部的细节不在这一份**（那是它自己那份文档的事，见 [§二](P0/02-screens.md) 的"细节在哪"）。
> **这一份是决策**，不是待选方案。
> 不写实现（组件名 / 常量名 / 文件路径 / "当前实现"）；不写外观（颜色 / 底色 / 字重 / 缩进值 / 边框样式）。
> 判据：`docs/DESIGN.md`（§2 结构 · §3 节点 · §4 角色 · §5 不变量 · §7 边界 · §9 作业）。两家的先例在 [`../screens/`](../screens/) · [`../components/`](../components/) · [`../commands/`](../commands/)（主屏的逐区对照是 [`../screens/S0-main.md`](../screens/S0-main.md)）。**凡两家已有的做法，本份的默认是照抄**（照抄的对象写明）；只有与 DESIGN 的硬约束冲突时才另立，并在该处写明冲突点。

**七个承重决策**（都是这一轮问过、定下来的）：

| # | 决策 | 结论 |
|---|---|---|
| 1 | 内容区放什么 | **三档 = 结构露出多少**：这段对话（不露）→ **盯住一条**（树的一小段 + 选中那行的实况）→ 整棵树（全露）；一个键循环 |
| 2 | 树占多大 | **占满内容区**（输入行那一带不动） |
| 3 | 侧边 | **要**，三态可切换：分成两栏 / 占满全屏 / 收起（照抄 jcode） |
| 4 | `esc` | 一个意思：**收掉最后出现的那一层**（"眼前"就是"最后出现"） |
| 5 | "谁在动"那一行 | **只在档 ① 画**；档 ② 那个位置让给树的一小段，档 ③ 也不画（同一件事不在两处说） |
| 6 | 几屏 | **八屏**（主屏 + 挑角色 + 挑模型 + 键位表 + 选中复制 + 对话内搜索 + 变更日志与关于 + 诊断日志）；**整屏树不是一屏**（它是主屏内容区的档 ③） |
| 7 | 屏怎么进 | **只有三条路**：修饰键 / 斜杠命令（敲 `/` 弹命令名单）/ 从正文点进去。**裸字符（`?`）不是入口，只是打字** |
