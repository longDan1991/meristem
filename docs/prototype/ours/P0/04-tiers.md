# 四、档位：同一块东西（结构）的三个尺寸（决策 1、2、5）

> 这一节属于 [`../P0.md`](../P0.md)（骨架 · 总体规划）。上一节 [`03-layout.md`](./03-layout.md) · 下一节 [`05-side.md`](./05-side.md)

**三档只有一条轴：你看见多少「结构」。** 这是照抄 jcode 的形状 —— 它的一个键循环是 `Chat`（一行一只的短名单）→ `Controls`（**同一份名单**，选中那行就地展开详情，≤ 聊天高/3）→ `FullPage`（整块消息区换成它）；而且**每一档都把选中画在「当场看得见的那份东西」上，窗口跟着选中滚**（它的画面与逐行出处见 [`../../reference/jcode.md`](../../reference/jcode.md) §12 的「swarm 三档实测」）。

**落到我们的东西上 —— 我们的名册是树。** jcode 的名册是平铺的 agent 表，所以它第二档还是那份名单；我们的结构只在树里，所以**第二档必须让结构露出来**：

| 档 | 我在看什么 | 结构露出多少 | 什么时候存在 |
|---|---|---|---|
| **① 这段对话** | 我站着的这条线的事 + 最底下一行「谁在动」（一行一条线：在跑几个 / 出错） | **不露** | **永远**（默认） |
| **② 盯住一条** | 内容区底部**向上长出一段树**：选中的那条 + 它的邻域（祖先 / 兄弟 / 直接子树折成 `▸ N 条`），**窗口跟着选中走**；选中那行**下面就地展开它的实况**（正在吐的尾巴 + 手上的活 + 名字·角色） | **一小段**（预算 ≤ 内容高/3，夹 3..16 行） | 树上**有我以外的线**时（只有我这一条 → 跳过这一档） |
| **③ 整棵树** | 整块内容区换成树（全量、可折叠、相机跟着选中） | **全部** | **永远** |

**一屏上三档各长什么样**（手画的示意图，`┃` 右侧是注解、不是屏幕内容）：

```text
─ ① 这段对话（默认） ────────────────────────────────────
… 它的话 / 思考 / 手的交代（我这条线的事）             ┃ 内容区 = 我这条线 + 最底下一行
…（一直往上翻）                                        ┃ 条长在内容区底部、状态行正上方
──────────────────────────────────────────             ┃ 一行一条「在动 / 出错」的线
▌分叉窗口 · coder  ▶1 · 整理 DESIGN ✗ · 看日志         ┃ 最多 3 行 + 1 行「还有 N 条」
▸ 还有 2 条                                            ┃ 没有活 → 整条不出现（树在休息）

─ ② 盯住一条（树的一小段 + 选中那条的实况） ─────────────
… 对话被挤短（我这条线的事照旧在上面）                 ┃ 段从内容区底部向上长
树段 3/8 · ▶2 在动                                     ┃ 段首一行计数（照抄 jcode 的 M/N active）
   ├ 整理 DESIGN · writer                              ┃ 树的一段：选中那条 + 邻域
 ▸ 分叉窗口 · coder          ▶1                        ┃ ★ 选中画在树段上（▸ + 加粗）
   │    正在吐的尾巴…                                  ┃ ★ 详情卡就地在选中行下面
   │    手上的活：bash 3.4s                            ┃ （accordion，不是另开一块）
   │    coder · 写实现                                 ┃ 窗口跟着选中滚 → 选中永远看得见
   ├ 看日志 · bare            ✗                        ┃ 这一档不画「谁在动」那条（让给它）
   └ ▸ 3 条                                            ┃ 直接子树折成一行
↑↓ 选 · enter 切过去 · esc 收掉                        ┃ 末尾一行键位提示

─ ③ 整棵树 ──────────────────────────────────────────────
根                                                     ┃ 整块内容区换成树（不是叠加）
├ 分叉窗口 · coder                   ▌ ▶1              ┃ 相机跟着选中（▸）滚
│ ├ 整理 DESIGN · writer                               ┃ 全量 + 可折叠（▸ N 条）
│ │ └ ▸ 3 条                                           ┃ 右端记号 = 谁在动 / 谁出错
│ └ 看日志 · bare                     ✗                ┃ 这一档也不画「谁在动」那条
└ 调研 · bare                                          ┃ 同一件事不在两处说
```

**五条规则**：

1. **一个键循环**，**不存在的档跳过**（树上只有我这一条线时，① ↔ ③ 直接来回 —— 这正是「看一眼树再收回来」的最短路径）。
2. **只换内容区**：壳（③④⑤）不动；侧边不动。
3. **「选中」只有一个**：档 ② 树段里 `▸` 停的那条 = 档 ③ 相机跟着的那条，同一个。**每一档都把选中画出来**（② 画在树段上、③ 画在树上）—— 这是 jcode 那条纪律：**选中不许画在当场看不见的东西上**。
4. **窗口跟着选中滚**（照抄 jcode）：`↑↓` 换选中时那段窗口跟着挪，**选中的那条永远在视野里**。
5. **`esc` = 收掉眼前这一层**：档 ③ 收掉树（落回 ② 的一小段）、档 ② 收掉那段（回 ①）、档 ① 收掉正在跑的那一手。**界面当场写着它现在会收掉什么**（"正在吐字"那行旁边；树里写着"`esc` 回正文"）—— 不让用户猜。

**那「谁在动」这条只在档 ① 画。** 档 ② 里那个位置**让给树段**（不重复画一份平行的名单；树行右端本来就带 `▶N` / `✗` 记号，段首还写一行 `树段 3/8 · ▶2 在动`，所以"还有哪些在动"照样看得见）；档 ③ 也不画。

**那「一手吐出来的原文」（整段、不裁剪）不在这个轴上** —— 它是材料，不是「看多远」，所以它不是一档：

1. **侧边的一页**（照抄 jcode 的 `observe` 页）：只跟**当前这一手**，显示手名与状态、吐出来的原文、吃进去什么（故事 12）；
2. 正文那张卡片上**就地展开**（`ctrl+o`，**omp 就是它**：`app.tools.expand`）—— 细节归下一份（内容区内部）。

**代价（写清楚）**：

- 档 ② 只在「树上有一条可以盯的线」时才有意义；
- 它占的高度从对话那里借（照抄 jcode：**≤ 内容高/3，夹 3 行以上、16 行以内**）—— 借多了，我的对话就被挤短；
- 档 ② 的窗口只覆盖选中那条的**邻域**：**视野外还在动的线看不到**（要看全局就 `esc` 回档 ①，或再进一档看整棵树）。
