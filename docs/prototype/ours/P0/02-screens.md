# 二、屏幕清单（定"有哪几屏" + "每一屏怎么进"）

> 这一节属于 [`../P0.md`](../P0.md)（骨架 · 总体规划）。上一节 [`01-stories.md`](./01-stories.md) · 下一节 [`03-layout.md`](./03-layout.md)

**八屏。**

## 2.1 进屏只有三条路（这一节的硬规则）

一个屏**只能**用这三种方式进。**裸字符键不是入口** —— 裸字符（`?`、`q`、`j`、不回车就敲一个 `/`）一律进输入行、变成正文。上一版把"进键位表"写成"按 `?`"，那是错的：按 `?` 只是往输入行里打一个 `?`（两家都不是这么做的，见右列）。

| 路 | 怎么走 | 什么时候用 | 两家就是这么做的 |
|---|---|---|---|
| **修饰键** | `alt+…` / `ctrl+…`（**不进输入框**） | 常开的面板 / 选择器 / 模式 | omp：模型 `alt+m`、名册 `alt+a`、重试 `alt+r`；jcode：复制模式 `alt+y`、swarm 面板 `alt+n`、会话选择器 `alt+r` |
| **斜杠命令** | 在输入行敲 `/` → **输入行上方弹出命令名单**（边打边过滤）→ 回车执行 | 没有键的那些屏；低频的 | 两家都有这条面（omp 84 条内置命令 / jcode 113 条可见命令）；`/help`、`/changelog`、`/debug` 全走它 |
| **从正文点进去** | 正文里的文件名 / 图片 / 改动处 | 这是"看材料"，不是"进一屏"（它开侧边，见 [§五](./05-side.md)） | jcode：点聊天里的图片开预览、点文件名开侧栏页 |

**以 `/` 开头的那一行不发模型** —— 它被当命令执行，这就是"斜杠命令"的全部含义。`/` 一打出来就先弹名单，所以命令名不用记。

## 2.2 八屏

| 屏 | 我什么时候会到这儿 | 怎么进 | 怎么出 | 细节在哪 |
|---|---|---|---|---|
| **主屏** | 我打开就在这里，平时一直在这儿 | 不"进" —— 打开就是它 | —— | **布局**见 [§三](./03-layout.md)：它里面的**内容区**（三档）→ [§四](./04-tiers.md)、**侧边**（三态）→ [§五](./05-side.md)，外加它自带的四行（状态行 / 输入行 / 事实行 / 键行） |
| **挑角色** | 分叉之前想换一套注意力与手 | 修饰键（两家的选择器都挂修饰键）—— **哪个键待定** | 选中即回；`esc` 取消（什么都不改） | 待写 |
| **挑模型** | 我想换这棵树用的模型 | `alt+m`（**omp 就是它**：`app.model.select`） | 同上 | 待写 |
| **键位表** | 我忘了某个键 | **`/help`**（斜杠命令；**jcode 就是它**，别名 `/?`、`/commands` —— 注意 `/?` 是**一条命令**不是裸 `?`；omp 是 `/hotkeys`） | `esc`（或 `q`） | 待写 |
| **选中 / 复制** | 我要把某几段单独拿走 | 修饰键（**jcode 就是 `alt+y`**：切换选择模式） | 复制完退出；`esc` | 待写 |
| **在对话里搜** | 我要在很长的一条线里找一句话 | `ctrl+r`（**两家都是它**：jcode `Ctrl+R` 搜跨会话历史、omp `ctrl+r` 搜历史） | `esc`；或选中一条跳过去 | 待写 |
| **变更日志 / 关于** | 我想知道这个版本改了什么 | **`/changelog`**（**两家都有这条**；版本是 `/version`） | `esc` | 待写 |
| **诊断 / 日志** | 出问题了，我要看现场 | 斜杠命令（omp `/debug`、jcode `/log`）—— **命令名待定** | `esc` | 待写（数据面归 `S11`，在 P2） |

**还没起名的键**（挑角色 / 诊断命令 / 档位循环 / 侧边三态与内容轮换）挂在 [§九](./09-open.md) —— 起名时要**比着整张键表**看，别撞车。

## 2.3 不是屏的东西（别把它们放回上面那张表）

| 东西 | 它其实是 | 为什么不算一屏 |
|---|---|---|
| **整屏树** | **主屏 · 内容区的档 ③**（见 [§四](./04-tiers.md)） | 它和"这段对话"是**同一个键循环里的两档**，不是从别处进去的另一屏 |
| **侧边全屏** | **主屏 · 侧边的一态**（见 [§五](./05-side.md)） | 一个键在三态里循环，屏没换 |
| **命令名单**（敲 `/` 弹出来的那张） | **输入行的一层浮层** | 它是"怎么进"的载体（2.1 的第二条路），不是屏；它长在输入行上方，属于它那一屏自己的一层 |

## 2.4 不做的屏（也是决策）

| 不做 | 为什么 |
|---|---|
| **会话选择器** | 我们只有**一棵树、一份账**（§7）—— "换哪一个会话"就是"在树里换一条线"，已由主屏的档 ③（整棵树）承担 |
| **agent 名册 / swarm 全屏页** | 那是"让模型自己拆完跑完"的可见面（§1 已驳） |
| **设置 / 主题 / 显示开关** | 不加旋钮（§5.5）；改这些是改文件，不是改界面 |
| **审批 / 计划确认 / 队列模式** | 都不是立身之处（各自在 [`../overview.md`](../../overview.md) §三 里有优先级） |
| **用量面板 / 账号 / 登录** | 没有账号体系；用量在底下那一行随时可见 |
| **首启向导 / 欢迎卡** | 空屏就是留白 + 一句提示（故事 1）—— 不需要一段"教你怎么用" |
| **协作 / 多端 / 分享** | 设计里只有一个人、一棵树 |
